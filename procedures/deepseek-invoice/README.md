# deepseek-billing — DeepSeek 开放平台账单页

> **作用域**：browser-use（浏览器界面）· **平台**：web · **驱动路线**：playwright（headless Chromium）
> **上次实测**：2026-10-23（金额读取与失败分支；「有额度」真实提交尚未真机验证）
> **驱动脚本**：本目录 `run.mjs` —— 这是这个界面的确定性操作，和界面档案放在一起，因为
> 它们同时失效：DeepSeek 改版时，选择器和「读不到金额必须报错」这个分支往往是同一次改动。

## 这个界面是什么

DeepSeek 开放平台的**账单页**（`https://platform.deepseek.com/transactions`），
用来给账户余额申请企业增值税普通发票。

| 特征 | 影响 |
|---|---|
| 需要登录态（cookie + localStorage 的 `userToken`，约 6KB） | 无状态不可跑；登录态会过期，失效时退出码 2 |
| 页面是 React 渲染，无公开 API 可用 | 只能驱动界面，不能走接口 |
| 金额在 `.ds-text / span / div` 的**最内层节点**，形如 `¥1,234.00` | 选择器失效 → **读不到金额**，必须按失败处理，不能当 0 |
| 发票抬头是自研自动补全组件 | 必须「输入 → 等下拉 → 点第一项」，不能直接提交 |
| 平台有风控，按 IP 判定 | 需要长期登录态 + 国内固定出口 IP |

## 入口与会话

- 入口：headless Chromium 打开 `https://platform.deepseek.com/transactions`
- 会话：`storageState` 文件（`auth/storage-state.deepseek.json`，权限 600），由本地 Chrome
  导出后裁剪到只含 deepseek 域再传到目标机
- 本界面**不**复用操作者已登录的 Chrome —— 它跑在无头服务器上

## 权限与前置

| 前置 | 说明 |
|---|---|
| Chromium | `playwright install chromium` + 系统依赖 |
| 登录态 | 见「登录态维护」 |
| 固定出口 IP | 平台按 IP 风控；云端 runner 每次 IP 不同且在境外，会被判可疑 |
| 发票抬头/税号/邮箱 | `config.json`（600），不入库 |

## 运行

```bash
node run.mjs --dry-run     # 只读：读金额、不提交
node run.mjs --live        # 真提交（金额 > 0 且未超上限时）
```

退出码：

| 码 | 含义 |
|---|---|
| 0 | 成功（含「金额明确为 0，跳过」） |
| 1 | 未捕获异常 |
| 2 | 登录失效，需重新导出登录态 |
| 3 | 金额超过 `maxAmount`，已中止 |
| **4** | **读不到可开票金额**（页面改版 / 未加载 / 匹配规则失效）—— 已截图，未提交 |
| **5** | **提交后未验证到成功提示** —— 人工核对，**不要自动重提**（可能已提交，重提会重复申请） |

只按退出码判定：4 / 5 都必须当失败处理。

## 安全设计

- **默认 dry-run**；只有部署侧的 unit 里显式 `--live`
- `maxAmount` 金额上限保护，超过即中止（退出码 3）
- 金额**明确为 0** 才跳过（天然幂等）；**读不到金额不算 0**，按失败处理（退出码 4）
- 提交结果不确定时按失败处理（退出码 5），不自动重提
- 登录态与配置被 `.gitignore` 排除，不进仓库
- 只操作 DeepSeek 一站点的账单页，不触碰其它系统

## 登录态维护

登录态会过期。刷新步骤：

1. 本地 Chrome 登录 `https://platform.deepseek.com`
2. 导出并裁剪为只含 deepseek 的 storageState（`cookies` 过滤 `domain` 含 deepseek；`origins` 只留 `platform.deepseek.com`）
3. `scp` 到目标机 `/opt/deepseek-invoice/auth/storage-state.deepseek.json`
4. `chmod 600`

失效信号：退出码 2，日志里出现「登录态失效」。

## 已知限制（踩坑实录）

- 发票抬头是 DeepSeek 自研的自动补全组件，**「有额度」场景尚未真机验证**；脚本按「输入 → 等下拉 → 点第一项」处理，首次真实提交建议人工旁看。
- 页面改版会导致选择器失效：读不到金额会以退出码 4 结束（截图留证），不会当成 0 静默跳过。
- 提交后若页面没有成功提示，只能判定「结果未知」（退出码 5）——脚本无法区分「已提交但提示没出现」和「提交失败」，因此必须人工核对，不能自动重提。

## 何时别用

- 需要用**另一种发票类型**（专用发票 / 按明细开票）：当前只实现「按充值金额开票 + 增值税普通发票」。
- 无法提供**长期登录态**或**国内固定出口 IP**：会频繁触发风控，维护成本高于收益。
- 金额会出现**部分开票**需求：脚本按全额提交，不支持拆分。
