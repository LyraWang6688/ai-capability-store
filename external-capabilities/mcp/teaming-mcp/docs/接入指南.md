# 接入指南（给使用者）

> 这份文档是给**使用者**看的。装完之后，你开完会自动收到会议分析报告——
> 不需要建飞书应用、不需要授权任何飞书权限、不需要填模型 key。

---

## 一、你需要准备什么

| 项 | 要求 |
|---|---|
| **AI 宿主** | 豆包工作 或 WorkBuddy（已装好并能正常对话） |
| **Node.js** | 20 或更高（终端执行 `node -v` 能看到 v20+ 即可） |
| **一个接入码** | 向管理员索取，形如 `KNTX7UCR`（8 位，不含 0/O、1/I/L） |
| **飞书账号** | 在宿主里已登录你**平时开会用的**那个飞书账号 |

> ⚠️ **豆包账号注意**：通过豆包登录飞书的那类账号，在飞书侧无法创建应用、
> 也无法授权第三方应用。本方案不需要你授权任何应用，所以**可以用**；
> 但请确认宿主里连的是你开会用的身份，否则读不到会议。

---

## 二、三步装好

### 第一步：安装

```bash
npm install -g teaming-mcp
```

装完会得到两个命令：`teaming-mcp`（MCP 服务）和 `teaming`（命令行）。

### 第二步：用接入码配好一切

```bash
teaming setup --code KNTX7UCR
```

把 `KNTX7UCR` 换成管理员给你的码。

它会把下面这些一次配好，写进 `~/.teaming-mcp/config.json`（权限 0600）：

- 你的**专属**服务器凭证（不是共用的）
- 报告接收地址
- 分析用的模型配置

**看到这行就成功了：**

```
✅ 配置已写入 /Users/你/.teaming-mcp/config.json
   归属集成：……
   模型端点：https://api.deepseek.com/v1
   分析模型：deepseek-flash
```

### 第三步：在宿主里加连接器

**豆包工作**：连接器 → 添加自定义 MCP，填：

```json
{
  "command": "node",
  "args": ["/你的路径/node_modules/teaming-mcp/src/mcpServer.mjs"]
}
```

**WorkBuddy**：编辑 `~/.workbuddy/mcp.json`，加一段同样的配置，
然后**在界面上手动信任一次**（只写文件不生效）。

> ⚠️ **不要**在这里填 `TEAMING_HOST_TOKEN` 之类的环境变量——
> 第二步已经配好了，环境变量的优先级更高，填了反而会覆盖掉你的专属凭证。

**找路径的办法：**

```bash
npm root -g
```

会输出类似 `/usr/local/lib/node_modules`，那么 `args` 就是
`/usr/local/lib/node_modules/teaming-mcp/src/mcpServer.mjs`。

## 三、验证

在宿主里让它跑一次 `teaming_doctor`，或者在终端执行：

```bash
teaming doctor
```

**应该看到：**

```
OK    lark-cli 可用
SKIP  飞书已授权        新架构下由宿主取数，MCP 不需要飞书授权
SKIP  会议搜索权限      同上
SKIP  妙记读取权限      同上
OK    分析引擎已构建
OK    分析凭证可用
OK    模型端点
OK    分析模型

可以开始使用。3 项已跳过（当前架构下不需要）。
```

> **3 项 SKIP 是正常的**，不是错误——逐字稿由宿主自己取，MCP 不碰飞书。

## 四、日常怎么用

### 手动分析一场会

在宿主里直接说：

> 分析一下我昨天那个会

宿主会自己去取逐字稿，交给 MCP 分析，约 **半分钟**出结果。

### 自动分析（推荐）

在宿主里建一个**定时任务**，提示词如下：

```
监控我在飞书会议中产生的妙记，发现新妙记就取逐字稿做团队动力分析并汇报。

执行步骤：
1) 用 lark-cli minutes +search 分别按 --owner-ids me 与 --participant-ids me
   查询最近 2 小时生成的妙记，按 token 去重合并；
   与上次已汇报过的 minute_token 比对，只处理新出现的。

2) 对每个新妙记，取逐字稿：
   lark-cli minutes +detail --minute-tokens <token> --transcript \
     --output-dir /tmp --as user --format json
   ⚠️ flag 是 --minute-tokens（复数）；必须显式传 --transcript；
      --output-dir 只允许 cwd 或 /tmp 或 ~/files
   读取返回的 data.minutes[0].artifacts.transcript_file 文件内容。
   拿不到逐字稿就如实说明，不要用 AI 摘要替代。

3) 调用 MCP 工具 teaming_analyze_transcript，传：
   transcript = 上一步读到的逐字稿原文
   title      = 妙记标题
   它会立刻返回 status=running 和 job_id（不要重复调用）。

4) 用 teaming_job_status 轮询同一个 job_id 直到 status=done
   （约半分钟，每 15~30 秒查一次）。

5) 汇报：团队状态定位、互动概览、未完成的对话与非共识、给领导者的建议，
   以及返回里的 reportUrl（带图表的网页报告页）。

约束：查询为空就如实说明原因，不要编造；同一份逐字稿重复分析会复用已有报告。
```

**频率建议**：工作日 08:00–23:00，每小时一次。

## 五、常见问题

### 报告说"逐字稿不合格"？

**分析只认成员原始发言**（每行形如「姓名 MM:SS 发言内容」）。
AI 摘要、会议纪要、待办列表都不算逐字稿，会被明确拒绝——这是有意的，
拿摘要去分析会得出假结论。

### 报"模型返回为空"？

DeepSeek 官方说明 JSON 模式下**有概率返回空内容**。引擎会自动重试与局部修复，
偶尔仍可能失败。**这与你的逐字稿无关**，重跑一次通常就好。

### 换了模型之后报告结论不一样？

**正常。** 引擎提示词是针对特定模型调的；同一份逐字稿在不同模型下，
Zone 判定可能不同——甚至同一模型跑两次，边界也会跳动。这是已知现象。

### 报告页链接打不开？

`reportUrl` 由服务器提供。卡片或对话里的链接如果指向飞书文档，说明
服务器报告接口没配上——找管理员。

### 重装/换电脑后会重复分析吗？

不会。**同一份逐字稿按内容哈希复用已有报告**，不会重复消耗额度。

### 我的数据在哪儿？

| 数据 | 位置 |
|---|---|
| 配置（含你的凭证） | `~/.teaming-mcp/config.json`（0600） |
| 报告与逐字稿 | `~/.teaming-mcp/.out/` |
| 任务记录 | `~/.teaming-mcp/.state/` |

从 git 检出直接跑时，后两项在仓库目录内（已在 `.gitignore`）。

## 六、卸载

```bash
npm uninstall -g teaming-mcp
rm -rf ~/.teaming-mcp          # 配置与本地数据
```

**别忘了**：让管理员吊销你的宿主凭证（服务端只存了它的哈希，可单独吊销）。
