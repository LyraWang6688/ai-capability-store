# 待发送队列（pending-queue）

右侧边栏里的一块草稿区：把还没准备发的想法先存下来，等手上这一件事做完，再挑一条推进当前会话。

## 它解决什么

DSH 自己的「排队」解决的是**同一个任务里**的插话：agent 跑着的时候你打的字按顺序排着，这一轮结束自动发出去。它解决不了另一种情况——

> 我又想起一件**独立**的事，但现在这个功能还没开发完，不能让它插进来；先记下来，等这轮收尾了再发。

这两件事长得像，其实不是一件事：前者是「排队发送」，后者是「攒着稍后发」。混在一起做，用户会发现关掉会话就丢了。所以这个插件单独存一份队列，什么时候推由你决定。

## 安装

插件以 npm 包形式分发，装进一个 DSH profile：

```bash
# 从 npm（发布后）
dsh plugin --profile desktop add @lyra_wang/dsh-pending-queue

# 本地开发：先打包，再从 tarball 装
npm pack
dsh plugin --profile desktop add ./lyra_wang-dsh-pending-queue-0.1.0.tgz
```

装完重启 DSH，右侧栏的「添加 tab」里会出现「待发送」入口。

## 用法

1. 在右侧栏打开「待发送」。
2. 在顶部输入框里记一条，`Cmd/Ctrl + Enter` 或点「存下」。输入框里可以直接**粘贴或拖入图片**（png / jpeg / webp / gif），也可以点「＋ 图片」选文件。没点「存下」的文字、引用和图片会按会话暂存在浏览器里，切走或重启 App 后回来还在。
3. 想带上引用：在聊天里选中一段文字，回到面板点「引用选中」，它会挂在这条下面；推送时还原成真正的引用块（和输入框的引用同源）。
4. 每一条可以：
   - **发送**：内容进输入框并立刻提交（agent 正在跑时会排进队列，不会打断当前任务）
   - **填入**：只放进输入框，你自己改两笔再回车
   - **编辑 / 删除 / ↑ ↓**：改内容、删掉、调整顺序
5. 发过的行标「已发送」，可以「取回」重新排队，或一键「清空已发送」。

## 实现要点

- **不写会话事件**。宿主半只有一份按会话拆开的 JSON，和两条同源路由（`GET /plugins/pending-queue/state`、`POST /plugins/pending-queue/action`），走 DSH 自己的连接鉴权。
- **一条记录 = 片段数组**（文字段 / 引用段 / 图片段），不是一段纯文本。图片存在本机 `<DSH_HOME>/storages/pending-queue/assets/<sessionId>/`，推送时插入 `@<路径>` 并附一句「请用 read_image 查看」——模型因此能“看到”这张图，只是需要主动读一次。推送时按片段重放：`setDraft()` 放开头的文字，`insertText()` 补后面的文字块，`insertQuote()` 还原引用块，最后 `submit()`。所以引用发出去就是真正的块引用，而不是字面的 `> ` 前缀。
- **发送走输入框自己的动作**，和你手打的一模一样——同样的排队语义、同样的回显、同样的失败处理，插件不另造一条发送通道。
- **按会话存**：`<DSH_HOME>/storages/pending-queue/<sessionId>.json`。两个会话不会共用一条队列；删掉这个文件就是清空。
- 面板每 10 秒静默同步一次，切回窗口也会同步；写入按读-改-写串行，两个窗口同时开着不会互相覆盖。

## 已知限制

- 拿不到输入框动作（`inputActions`）的位置只提示「填入失败」，不会退化成剪贴板或 DOM 注入——那种兜底会绕开 DSH 自己的提交路径。
- **图片不是附件**：DSH 的附件只能由输入框的选文件/粘贴流程产生（浏览器内存里的 `File` + `DraftAttachmentId`），插件面板造不出来。所以图片以“本机路径 + read_image 提示”进对话，模型需要多一次工具调用才能看到图。
- **`@` 引用 chip 对不齐**：读得到（`InputState.occurrences`）但没有公开的插入接口，还原只能退化成文本。
- 队列只在当前机器上，不跨设备同步。
- 「已发送」的行是留痕，不自动清理；不想看就点「清空已发送」。

## 版本

- 0.1.0 — 首个版本：新增、编辑、删除、排序、发送、填入、已发送留痕。
- 0.5.2 — 输入框底部的提示文字不再被挤成竖排：提示独占一行，按钮在下一行右对齐。
- 0.5.1 — 自动归位：待发 / 已发 / 已删除按这个顺序分组（组内保持原序）；标为已发送或删除后自动落到最下面，恢复后回到待发区末尾。
- 0.5.0 — 软删除：「删除」改为划横线的软删除（行留在原位，可「恢复」或「彻底删除」），已删除的行不能编辑/移动/发送；表头多一个「清空已删除」。
- 0.4.0 — 飞书引用：面板里的「飞书引用」按钮复用 feishu-ref 插件的搜索（`POST /plugins/feishu-ref/search`），选中文档 / 云盘 / 群 / 消息 / 联系人后，插入与输入框完全相同的引用文本。
- 0.3.3 — 编辑态补上「引用选中」：编辑某条时也能把聊天里选中的文字加进去，和草稿区一致。
- 0.3.2 — 编辑态也能加图：点「编辑」后，在编辑框里粘贴/拖入图片同样生效，编辑项里也有「＋ 图片」。
- 0.3.1 — 粘贴更稳：剪贴板只给 `items` 不给 `files` 的截图也能接住；补「＋ 图片」选文件入口；未存下的草稿按会话暂存到 localStorage。
- 0.3.0 — 图片：面板可粘贴/拖入图片，存本机、条目带缩略图，推送时按“路径 + read_image 提示”进对话；删除行时清理不再被引用的图片文件。
- 0.2.0 — 引用：一条记录改成分段结构（文字 / 引用），面板可「引用选中」聊天里的文字，推送时还原成真引用块。
- 0.1.1 — 补上 `icon.svg`。0.1.0 的 `package.json` 声明了 `icon` 与 `./icon` 导出，但文件没进包，插件管理器读元信息时 `lstat` 失败，列表里会显示「包元信息错误」。
