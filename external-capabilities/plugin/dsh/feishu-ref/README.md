# feishu-ref

**在 DSH 输入框点「＋ 引用」，面板从输入框上方长出来：顶部一排类型 chip（全部 / 文档 / 云盘 / 群聊 / 消息 / 联系人），中间是最近使用或分组结果，搜索框在最下面。选中一条，一段 agent 能直接拿去读的引用就插进草稿。**

不需要切换飞书 App、不需要复制粘贴 URL：选中一条，引用文本就直接出现在输入框里，回车发出去，agent 就能顺着它去读那篇文档、那个群、那条消息或那个人。

> 能力边界（0.7.0）：只做「搜飞书 → 把内容变成 agent 的上下文」，并展示本机浏览器的「最近使用」。
> **不包含**自动在右侧浏览器打开文档（该能力依赖第三方插件拿不到的 sidebarRight 服务，已移除）。

## 插入的是什么（这是核心）

不是"一个名字"，而是 agent 拿着就能取到内容的东西：

| 类型 | 插进草稿的内容 | agent 怎么用 |
|---|---|---|
| 云文档 / 多维表格 / 表格 / 知识库 / 幻灯片 | `[标题](飞书 URL)` | 顺着 URL 读正文 |
| 云盘文件 / 文件夹 | `[文件名](飞书 URL)` | `drive +preview` / `+download` 读文件；文件夹用 `files list` 列目录 |
| 群聊 | `[群名](AppLink …openChatId=<chat_id>)` | `im +chat-messages-list --chat-id` 读群消息 |
| 飞书消息 | `[群名 · 发送者](AppLink)（message_id: om_…）` | `im +messages-mget --message-ids` 取原文——**AppLink 本身不带消息 ID，所以额外带上** |
| 联系人 | `[姓名](AppLink …openChatId=<p2p_chat_id>)（open_id: ou_…）` | 读私聊 / 查人 / 发消息；没私聊过的人只带 `open_id` |

## 使用

1. 输入框左侧出现「＋ 引用」按钮（紧挨系统「＋」）；
2. 点击 → 面板从输入框上方展开，**顶部是常驻的类型 chip**，搜索框固定在面板最底部（和豆包「＋」面板同一套逻辑）；
3. 还没输入时只列**最近使用**（本机最近选过的 6 条，不请求飞书，打开面板零延迟）；chip 也能按类型筛最近使用；
4. 在底部搜索框输入关键词，220ms 防抖后**五路并行搜索**（文档 / 云盘 / 群聊 / 消息 / 联系人），列表按类型分组；
   「全部」每组限行以保证同屏可见，点某个 chip 看该类型全量；
5. ↑/↓ 选择，回车插入（也可以鼠标点）；Esc 关闭；
6. 插入的是可撤销的文本，可编辑，不会自动发送。

## 数据来源（只读）

复用本机已认证的 `lark-cli`（用户身份），五条搜索在宿主侧并行发出、各自兜底：

- 文档：`drive +search --doc-types docx,bitable,sheet,wiki,slides`
- 云盘：`drive +search --doc-types file,folder`——**单独一路**：混在文档里搜时文件会被在线文档挤掉（实测搜「报告」混搜 0 条文件、单搜 8 条）
- 群聊：`im +chat-search --search-types private,external,public_joined`
- 消息：`im +messages-search`（必须有关键词，只搜你能看到的会话）
- 联系人：`contact +search-user`（user 身份；需要 `contact:user:search`，查人资料另需 `contact:user.basic_profile:readonly`）

群聊/私聊/消息链接都用飞书 AppLink。不用 `lark-cli im chats link`：那条返回的是 `add_by_link` **拉人入群**的邀请链接，还会过期，不是「打开」。

## 安装

前置：DSH 桌面端 + 本机已登录 `lark-cli`（`lark-cli auth status` 显示 user ready）。

```bash
dsh plugin --profile <profile> add @lyra_wang/dsh-feishu-ref
```

联系人分组需要额外授权两个 scope：

```bash
lark-cli auth login --recommend --scope "contact:user:search,contact:user.basic_profile:readonly"
```

> ⚠️ `--scope` 是**收窄**语义：只传 `--scope` 会把已有 scope 换成这两个。必须像上面这样和 `--recommend`（或 `--domain`）叠加，才是"原有全部 + 这两个"。

没授权时面板里只显示一行「联系人搜索失败：缺少授权：contact:user:search」，其它分组照常可用。

装完重启 DSH；输入框左侧即出现「＋ 引用」。

## 边界

- 只插入引用（链接 / ID），不上传附件、不改文档权限；
- 云盘文件只能打开 / 下载 / 预览，不像 docx 那样能直接读正文；文件夹只能列目录；
- 消息搜索必须有关键词、且只搜你可见的会话；联系人只搜你能看到的人；
- 群聊只列「已加入 / 外部 / 已加入的公开群」，未加入的公开群不出现；
- 搜索失败时面板内显示真实错误（常见：`lark-cli` 未登录 / 网络 / scope）；某一类失败不影响其它类；
- 输入框拿不到插入 API 时降级为写剪贴板，并在面板里提示「已复制到剪贴板」，不再静默失败；
- 不访问网络外发任何数据，所有请求都发往本机 DSH 的同源路由。

## 版本记录

### 0.7.0：五类统一——文档 / 云盘 / 群聊 / 消息 / 联系人

- 新增**云盘**（文件 + 文件夹）：`drive +search` 支持 `file/folder`，独立成一路搜索保证不被文档挤掉；行内显示扩展名（`PPTX · 3 天前`）与「文件夹」；
- 新增**飞书消息**：`im +messages-search`，行内显示「发送者：正文摘要」，右侧是「群名 · 时间」；插入时带 `message_id`，agent 可直接 `im +messages-mget` 取原文；
- 新增**联系人**：`contact +search-user`，显示姓名 + 部门 / 外部联系人；插入私聊 AppLink + `open_id`；未授权时只降级成一行红字提示；
- 面板顶部**常驻类型 chip**（全部 / 文档 / 云盘 / 群聊 / 消息 / 联系人），chip 也能筛选「最近使用」；
- 宿主路由改为五路 `Promise.allSettled`：单类失败只报该类，全部失败才 500；错误信息把 lark-cli 的英文 `missing required scope(s)` 翻成人话「缺少授权：contact:user:search」；
- 类型图标补齐文件 / 文件夹 / 消息 / 联系人。

### 0.6.0：面板改成豆包式（搜索框在底部）

- 面板从「浮在输入框上方的卡片」改成**输入框向上延展的一块**：与输入框同宽、同一个表面色/圆角 token，
  底部无边线，视觉上和输入框是一张卡；
- **搜索框移到底部**（对齐豆包「＋」面板的展示逻辑），不再在顶部；

- 搜索结果改为**单列分组**（文档 / 群聊，组标签吸顶），每组限行以保证两组同屏可见；
- 行样式向豆包看齐：16px 类型图标 + 单行标题 + 右侧灰色元信息（类型 · 时间 / 群描述 / 外部群）；
