# computer-automation/ — 电脑自动化文档区

> **这不是第五个资产域。** 不登记 `registry.yaml`，不参与 Store 的资产口径。
> 只收「怎么操作浏览器 / 怎么操作电脑」的交接文档。可复用的流程成熟后再升级成 Skill（见文末）。

## 怎么用（读的人先看这段）

**读者是下一个要重做同一件事的 Agent。** 它没有写文档那次会话的记忆，也不会去猜。

```
① 选架     browser-use/（浏览器） 或 computer-use/（桌面）

② 找软件   <app>/                  一个软件一个文件夹

③ 找功能   <app>/<功能>.md         文件名就是功能，如 cdp-takeover、window-capture

④ 按顺序读 抬头四条 → 工具清单 → 可复现步骤 → 踩坑实录 → 何时别用
```

三件必须知道的事：

- **没有对应文件 = 这件事还没人做过**，不等于做不到。别把"文档里没有"当成"能力不存在"。
- **抬头四条是可信度开关**：`结论` 写着「未验证」的，别照抄。
- **工具清单要看前置条件**：缺权限/缺服务的步骤，照抄会失败。

## 一篇文档回答五个问题

| 你心里的问题 | 对应小节 |
|---|---|
| 这篇可信吗、还适用吗 | 抬头四条：环境 / 实测日期 / 验证方式 / 结论 |
| 我有没有这些工具 | `## 工具清单` —— 工具 / 类型 / 用途 / **前置条件** |
| 具体怎么做 | `## 可复现步骤` —— 顺序 + **每步的观察点** |
| 卡住了怎么办 | `## 踩坑实录` —— 症状 → 原因 → 修法 |
| 该不该用它 | `## 何时别用` |
| 缺权限会怎样（桌面类） | `## 权限前提` |

**五节以内。** 小节数量本身就是阅读成本：选这条路的理由写进第 1 步，
每步的观察点就是验证，最后一步就是收尾——不单独开 `操作手段` / `如何验证` / `回退`。

## 结构

```text
computer-automation/
├── README.md              # 本文件
├── browser-use/           # 浏览器操作
│   ├── README.md          # 索引
│   ├── <topic>.md         # 不属于任何软件的通用主题
│   └── <app>/             # 一个软件一个文件夹
│       ├── README.md      # 索引：已写的功能 + 待建的功能
│       └── <功能>.md
└── computer-use/          # 桌面操作（同上结构）
```

**文件夹 = 软件，文件名 = 功能。** 同一个软件今天加一个功能、明天加一个，
文档会一篇篇多起来，所以用文件夹收录；**文件名是 Agent 的检索键**，
要能只看名字就判断"这篇是不是我要的"。

反例：`basic-operation` / `misc` / `notes` —— 说了等于没说。

## 写的时候

```bash
# 生成骨架并登记索引
python3 skills/computer-automation-log/scripts/new_doc.py \
  --kind computer --slug <功能名> --title "<标题>"

# 门禁：exit 0 才算交付
python3 skills/computer-automation-log/scripts/check_doc.py <doc.md>
```

必须给三样东西：**工具清单**（用了什么）、**可复现步骤**（走通的路）、
**踩坑实录**（没走通的教训）。只写结论的文档只完成了一半。
规则细节见 [`doc-contract.md`](../skills/computer-automation-log/references/doc-contract.md)。

## 不收什么

- 某个任务的具体 SOP → `skills/`
- 可调用的工具实现 → `external-capabilities/`
- 外部依赖的已知 bug → `docs/known-issues/`

## 何时升级成 Skill

三条同时成立：同一套步骤被重复用 ≥ 2 次；能写成不依赖会话上下文的「判断 → 动作」；
有可验证的产出。升级时按 `SKILL-FORMAT.md` 建 Skill，本目录对应文档缩成一个链接。
