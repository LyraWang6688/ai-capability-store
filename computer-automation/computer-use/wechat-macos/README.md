# 微信（macOS 桌面版）—— 界面档案

> 环境：macOS 桌面端 / 微信桌面版 4.x（主窗口进程 `WeChat`，小程序与内置网页由 `WeChatAppEx` 承载）
> 实测日期：2026-10-25
> 验证方式：窗口级截图逐屏核对；AX 树只暴露窗框；关键页用 OCR 复核文字
> 结论：已验证 —— 能通过合成鼠标事件完成小程序与内置浏览器的表单操作，但内容区不可被 AX 读取，定位只能靠截图/OCR

## 这个界面是什么

微信桌面版里同时跑着三类界面，操作方式各不相同：

| 界面 | 窗口名（`CGWindowList` 里的 `kCGWindowName`） | 承载进程 | AX 可读内容 |
|---|---|---|---|
| 主窗口（聊天、搜索、通讯录） | `Weixin` / `WeChat (Window)` | `WeChat` | 否 —— 只有窗框和三颗交通灯按钮 |
| 小程序（如「腾讯充值」） | 小程序名（如 `腾讯充值`） | `WeChatAppEx` | 否 |
| 内置浏览器（公众号 / 客服 / H5） | 页面标题，如「如何申请发票？ - 腾讯客服」 | `WeChatAppEx` | 否 |

结论先行：**不要指望 AX 读内容**。AX 只够用来读写窗口位置、最小化、raise 与聚焦；
页面里有什么、按钮在哪，只能靠 `screencapture` + OCR / 按窗口相对坐标换算得到。

## 窗口与进程标识

- bundle id：`com.tencent.xinWeChat`
- 主窗口通常铺满屏宽的一部分（`Weixin` 与 `WeChat (Window)` 会同时出现，一个是主窗、一个是内置浏览器窗）
- 小程序、内置浏览器都是**独立窗口**，会被主窗口盖住；窗口位置每次重排都会变，**不要缓存坐标**
- 本机实测版本：微信 4.x（`WeChat` 目录 Version=269602）

## 授权前提

| 权限 | 缺了会怎样 | 怎么确认 |
|---|---|---|
| 辅助功能（Accessibility） | `CGEvent` 合成点击/键入静默无效；AX 读写窗口失败 | `AXIsProcessTrusted()` 返回 `true` |
| 屏幕录制（Screen Recording） | `screencapture` 出黑图或空图 | 截一张全屏图能看见内容 |
| 自动化（Apple Events） | `osascript -e 'tell application "System Events" …'` 返回 `-10004` | 该错误即未授权；本机即为此状态，故**不用 AppleScript 驱动微信** |

## 能怎么驱动

- `cgevent`：合成鼠标点击、键盘、粘贴（⌘V）—— 本机唯一可用的输入通道
- `ax`：只用于窗口级动作（`AXPosition` / `AXSize` / `AXMinimized` / `AXRaise` / `AXFocused`）
- `screencapture`：`-l <windowId>` 抓单个窗口（不受遮挡影响）、`-R` 抓区域（Retina 下像素是点数的 2 倍）
- `applescript`：**已死**（`-10004`），不要在这条路上花时间

## 已知坑（汇总，细节见各功能文档）

1. 宿主（DSH 桌面端）窗口会反复抢焦点 —— 点击会被它吃掉；操作前先把它最小化或移出点击区域。
2. `open -a WeChat` 会把微信**主窗口**抬到最前，反而盖住你要点的小程序/浏览器窗口；要抬哪个窗口就用 AX 对该窗口 `AXRaise`。
3. 合成点击对普通按钮有效，但对文本框需要**点中占位符文字本身**（偏上约 20 点就不聚焦）。
4. 窗口位置在两个工具调用之间会变，写死坐标等于随机点击。
