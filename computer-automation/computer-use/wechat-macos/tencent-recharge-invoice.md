# 腾讯充值发票（增值税普通发票）申请流程

> 环境：macOS / DSH 桌面端 / 微信桌面版 4.x / 已登录微信号（`WeChatAppEx` 承载小程序与 H5）
> 实测日期：2026-10-25
> 验证方式：窗口级截图逐屏核对；开票记录页出现新单（金额 ¥57.00、状态「开票中」）；OCR 读到「申请成功 / 您提交的开票申请已受理」
> 结论：已验证 —— 3 笔订单合并开一张普通发票全流程走通；卡点是合成点击的落点精度与宿主抢焦点

## 权限前提

- **辅助功能**：`CGEvent` 点击/键入、AX 读写窗口都依赖它。未授权时点击静默无效（不报错、页面不动）——这是本流程最容易被误判为「页面卡住」的失败模式。
- **屏幕录制**：`screencapture` 依赖它；未授权时截图为黑，后面所有定位都会落空。
- **自动化（Apple Events）**：本机 `System Events` 返回 `-10004`（未授权），因此**不能用 AppleScript UI scripting 点击/输入**，只能走 AX API + CGEvent。想用 AppleScript 就先解决授权，否则别试。

## 工具清单

| 工具 | 类型 | 用来做什么 | 前置条件 |
|---|---|---|---|
| `screencapture -l <windowId>` | 系统 CLI | 抓单个窗口（遮挡也能抓到内容）；`-x` 静音 | 屏幕录制授权 |
| `screencapture -R x,y,w,h` | 系统 CLI | 抓屏幕区域，Retina 下像素 = 点数 × 2 | 同上 |
| Swift + `CGEvent`（自建） | 合成事件 | 移动/点击、⌘V 粘贴；`click` 与 `click2`（带 mouseMoved + clickState） | 辅助功能授权 |
| AX API（`ApplicationServices`） | 系统 API | 读 `CGWindowList` 找不到的窗口属性、设 `AXPosition`/`AXSize`、`AXMinimized`、`AXRaise`、`AXFocused` | 辅助功能授权 |
| Swift + Vision（`VNRecognizeTextRequest`） | OCR | 在截图里定位「（申请入口）」这类文字，换算成全局点坐标 | 无 |
| `pbcopy` + ⌘V | 系统 CLI + 合成键 | 写入中文（直接合成 Unicode 键入对微信网页不稳） | 辅助功能授权 |

## 可复现步骤

入口链条固定：**微信搜索「腾讯充值」→ 小程序底部「我的帐户」→「申请发票」→ 微信内置浏览器（腾讯客服页）→ 普通发票申请入口 → 选单 → 填抬头 → 提交**。

1. **列出窗口，锁定目标**。用 `CGWindowListCopyWindowInfo` 过滤 `owner=WeChat`，拿到三件事：小程序窗口名（如「腾讯充值」）、内置浏览器窗口名（页面标题）、两者的 `bounds`。观察点：能`id/bounds`地列出窗口，且 `onscreen=1`。
2. **打开小程序**。微信主窗口搜索框输入「腾讯充值」→ 回车。观察点：出现名为「腾讯充值」的独立窗口，窗口截图里有「电子发票开具成功通知」卡片和底部三个 tab（进入商城 / 专属福利 / 我的帐户）。
3. **进入「我的帐户」菜单**。点击底部「我的帐户」。观察点：弹出一列菜单：我的余额 / 充值记录 / 续费管理 / 积分兑换 / **申请发票**。
4. **点「申请发票」**。观察点：微信内置浏览器窗口出现，标题「如何申请发票？ - 腾讯客服」。
5. **选普通发票入口**。页底有两行链接，**只差一行**：
   - `开具增值税普通发票，请点击（申请入口）`
   - `如您是受公司委托采购，需开具增值税专用发票，请点击（申请入口）`

   点第一行末尾的「（申请入口）」。观察点：跳到微信授权页（头像 + 微信号字样 + 「申请发票」蓝色按钮 + 「开票记录」白按钮）。
   点错到第二行会进入「开具增值税专用发票须知」（要营业执照复印件与开票声明），退回去重点即可。
6. **进入选单页**。点「申请发票」。观察点：标题变「申请发票」，页面出现「请选择申请发票订单」、右侧「最近三个月订单」下拉、订单列表（商品名 + 支付时间 + 金额）。
7. **勾选订单**。左侧复选框逐笔勾选。观察点：底部「总价：¥xx.00」随勾选累加；全空时「下一步」是灰的，勾选后变蓝。
8. **下一步 → 抬头类型**。观察点：出现「请选择抬头类型：个人 / 组织 / 公司」，并显示「发票类型：电子发票（增值税普通发票）」；未选类型前「提交」是灰的。
9. **选「组织」并填表**。观察点：表单出现只读行「发票主体：深圳市腾讯计算机系统有限公司」「发票项目：*生产生活服务*文学」「发票金额：¥xx.00」，以及两个输入项：`*发票抬头名称`、`统一社会信用代码`。
   - 输入必须**点中占位符文字本身**（`请填写发票抬头` / `请填写统一社会信用代码`），偏上约 20 点会点空、粘贴进不了框。
   - 用 `pbcopy` + ⌘V 粘贴中文；粘贴后截图确认框内出现文字与光标。
10. **提交 → 二次确认**。点蓝色「提交」。观察点：弹出「发票申请提交后不可修改，请确认内容无误后再提交」，下方「取消 / 确认」；点「确认」。
11. **核对结果**。观察点：页面出现「申请成功 / 您提交的开票申请已受理」，并写明普通发票约 5 个工作日处理、「开票记录」可查进展。
    回到「申请发票 / 开票记录」页 → 点「开票记录」→ 列表第一行即新单：金额一致、状态「开票中」、有开票单号；旧单显示「已开票」。
12. **收尾**。关掉内置浏览器窗口，把被最小化的宿主窗口恢复；小程序窗口可保留（下次申请还要用）。

## 踩坑实录

| 症状 | 原因 | 修法 |
|---|---|---|
| 点「我的帐户」/「（申请入口）」完全没反应，页面像冻住 | 目标窗口不是 key window（宿主窗口在前），第一次点击只用于激活被吞掉；或坐标偏上≈20 点没落在文字上 | 先对该窗口 `AXMain=true` + `AXFocused=true` + `AXRaise`，再点；坐标以 OCR 返回的文字框中心为准 |
| `osascript -e 'tell application "System Events" to keystroke …'` 报 `-10004` | 没有「自动化」授权 | 放弃 AppleScript，改用 CGEvent + AX API |
| `open -a WeChat` 之后要点的窗口反而被盖住 | 激活 app 会把它的主窗口抬到最前 | 别用 `open -a`；直接对你想要的窗口 `AXRaise` |
| 两次工具调用之间页面位置全变了，写死的坐标点空 | 窗口在被 raise / 激活后重排（宽高、原点都会变） | 每次操作前重新取 `bounds`，用「窗口相对比例」或 OCR 现算，别缓存 |
| 点「申请入口」进了「专用发票须知」 | 两个入口上下只差一行，y 差约 20 点 | 用它所在那行文字的 OCR 框末尾去点；进错页用浏览器后退即可 |
| 粘贴中文进不了输入框 | 输入框没聚焦（点击落空），或页面对合成键入不认 | 确认点击命中占位符后，用 `pbcopy` + ⌘V；粘贴后立刻截图验证框内文字 |
| 宿主（DSH 桌面端）窗口不停回到最前，点击全被它吃掉 | 宿主窗口抢焦点 | 用 AX 把它 `AXMinimized`，或把目标窗口移到它不覆盖的位置再操作 |

## 何时别用

- **有接口就不要走这里**：腾讯侧若能拿到商户后台 / 发票服务 API，走 API；本流程只适合「平台只给了小程序 + H5」的情况。GUI 是最后手段。
- **不要把它写成写死坐标的定时脚本**：微信窗口每次重排位置都会变，界面改版也不报错，只会点错地方——这是 Computer Automation 域最典型的静默失效。真要做成自动化，定位必须走 OCR / 界面结构，并配「找不到入口就退出码非 0」的失败分支。
- **需要 trusted gesture 的交互（弹窗、新窗口）先小范围验证**：合成点击在部分页面会被浏览器当作非用户手势拦截。本次流程实测没有被拦，但换页面/换版本要重新确认。
- **开票是外部不可逆动作**：提交前必须有人确认抬头、税号、金额；提交后平台不提供修改，错了只能走客服。
