# 豆包工作（Doubao Work）桌面操作

> 环境：macOS / DSH 桌面端 0.2.1-rc.2 / DoubaoWork.app 2.33.5（Chromium 147 内核）/ 辅助功能未授权
> 实测日期：2026-10-24
> 验证方式：CDP 读 `/json/version` 与页面列表 + DOM 断言（入口、输入框、`<img>` 数量）+ 截图 + 自建 MCP 服务端日志
> 结论：已验证 —— CDP 可完全驱动该 App；自定义 MCP 连接器能连本机服务，但工具返回的图片不会被渲染

## 权限前提

| 权限 | 本机状态 | 影响 |
|---|---|---|
| 辅助功能 | **未授权**（System Events 报 `-10004`） | AppleScript 模拟键鼠全部失效，只能截屏看 |
| 屏幕录制 | 可用 | `screencapture` 能截到窗口 |
| 应用自身数据目录可写 | 必须 | 进程要写 profile 的锁文件；写不了会打印 `SingletonLock` 失败并**自保护退出** |

关键结论：**不依赖辅助功能**。把驱动方式换成 CDP，才绕过这一条。

## 操作手段

主手段是 **CDP（Chrome DevTools Protocol）**，不是截图点击。

- 判断依据：该 App 的框架是 Chromium 147。能否连上，用 `/json/version` 是否返回浏览器版本即可确认。
- 做法：先正常退出应用，再直接执行 App 主二进制并附加 `--remote-debugging-port=<空闲端口>`。
- 为什么选它：辅助功能不可用；DOM 级读取比截图判读可靠，而且能拿到"入口在不在""输入框在不在""图片有几张"这类可断言的事实。
- 端口选择：避开 `9222`（本机 Chrome 的调试端口常在用它），换一个未被占用的端口。

## 如何验证

1. `GET /json/version` 返回浏览器版本 → 调试通道已开。
2. `GET /json` 列出页面 target；主界面是内部页面 `doubaowork://doubaowork-chat/chat`。
3. DOM 断言：能读到侧栏入口「插件 · 技能 · 伙伴」，能定位到输入框，能数出页面里的 `<img>` 数量。
4. 截图存档，用肉眼复核 DOM 断言。

另外，自建 MCP 服务端的日志能看到 App 发来的握手序列：`server/discover` → `initialize` → `notifications/initialized` → `tools/list` → `tools/call`。这是"它真的连上了并调用了工具"的硬证据，比界面截图更可靠。

## 回退

- 结束带调试参数的进程，用 `open -a DoubaoWork` 正常启动即可恢复；调试参数只对那一次进程有效。
- 在 App 里加的测试连接器，用完在「插件 · 技能 · 伙伴 → 连接器 → 个人」里删除；删除入口在详情弹窗底部的「…」菜单。
- 测试对话可在会话列表里删除。
- 插件安装日志目录只需留着，它只是记录，不影响运行。

## 何时别用

- **只想读页面内容**：走 `web_fetch` 或官方 API，不要开 CDP。
- **目标应用有官方 CLI / API**：优先它们，驱动界面是最后手段。
- **生产账号或他人机器**：CDP 能看到真实会话数据，不要在非本人环境上做。
- **只需要点一下**：先看有没有快捷键或可改的配置文件，改文件比驱动界面便宜。

## 已验证的能力边界（MCP 连接器）

在本机起了一个最小的 MCP 服务（只暴露一个返回红色方块 PNG 的工具），把 App 当宿主做了四组对照：

| 测什么 | 结果 | 证据 |
|---|---|---|
| 自定义 MCP 连接器（**本机 HTTP 地址**） | ✅ 能安装、能握手 | 表单注明「自定义连接器仅支持在本地电脑中使用」；服务端日志收到 `initialize` 与 `tools/list` |
| 工具返回 `image` 内容 | ❌ 不渲染 | 工具调用成功，但页面 `<img>` 数量为 0；模型仍回复"已正常显示"（与事实不符） |
| Markdown 图片 · **公网 HTTPS** 地址 | ✅ 渲染 | DOM 里出现对应 `<img>` 且有实际宽高 |
| Markdown 图片 · **本机地址** | ❌ 被拦 | 渲染成占位图，取不到自然尺寸 |

结论：想让 App 显示一张图，图片**必须先在公网 HTTPS 上可访问**。指望"MCP 工具直接返回图片内容"让它内联显示，这条路不通。

## 已知坑

- **端口冲突**：`9222` 常被本机 Chrome 占用。换端口即可，别误判成"App 不支持调试"。
- **启动失败先读日志**：profile 锁文件写不了时应用会静默退出，日志里是 `ProcessSingleton` / `SingletonLock` 字样。
- **辅助功能与 CDP 是两条独立路线**：辅助功能被拒不代表不能自动化，先确认目标是不是 Chromium 内核，再决定路线。
- **模型的自述不可信**：它会一本正经地说"图片已显示"。判断是否真的渲染，必须用 DOM 断言（`<img>` 数量与自然尺寸）复核。
