# 给豆包工作装「技能」（三条来源与当前边界）

> 环境：macOS / DoubaoWork.app 2.33.5 / 已登录账号
> 实测日期：2026-10-24
> 验证方式：CDP 读 DOM 取「插件 · 技能 · 伙伴」页面结构 + 「+」菜单项文本 + 分类计数；未做上传实测
> 结论：部分验证 —— 技能的入口与三条来源已确认；「上传技能」的文件格式与生效链路未实测

## 这个 App 的「技能」是什么

侧栏「插件 · 技能 · 伙伴」里，技能是与插件、连接器并列的一类东西，数量远多于另两类：

| 类别 | 实测计数 |
|---|---|
| 插件 | 14 |
| **技能** | **179** |
| 连接器 | 16 |

## 权限前提

| 前提 | 说明 |
|---|---|
| 已登录 App 账号 | 技能列表与安装入口都跟账号走 |
| 能打开「插件 · 技能 · 伙伴」 | 侧栏可见即可，无需系统权限 |
| 上传技能时可能受企业管理策略限制 | 菜单里同时有「前往企业管理后台」，说明存在管理员维度 |

不需要辅助功能、不需要屏幕录制（用 CDP 读 DOM 即可，见 [cdp-takeover.md](./cdp-takeover.md)）。

## 操作手段

入口只有一个：**「插件 · 技能 · 伙伴」→ 插件页右上角的「+」**。点开后的菜单实测有四项目：

| 菜单项 | 用途 |
|---|---|
| 与豆包对话新建技能 | 用对话把常用步骤/模板/输出标准存成技能 |
| **上传技能** | 导入技能（**格式未实测**） |
| 新建自定义连接器 | 走 MCP，见 [mcp-connector.md](./mcp-connector.md) |
| 前往企业管理后台 | 管理员维度，个人账号看不到内容 |

要点：**"技能"不等于"只能对话创建"**。之前只看官方介绍会以为只能对话新建，实际菜单里存在「上传技能」这条导入路径。

## 如何验证

| 断言 | 方法 |
|---|---|
| 技能与插件、连接器是并列的三类 | 读页面顶部的 tab 文本：插件 / 技能 / 工作伙伴 |
| 三条来源都存在 | 点开「+」读菜单项文本 |
| 技能数量 | 筛选面板里的计数（技能 179） |

**都只到了"入口与形态"这一层。** 要验证"上传后真的能用"，还需要一次真实上传，这部分没做。

## 回退

- 装的技能按 App 内正常方式卸载；菜单与列表都在同一页。
- 上传失败的残留文件不会落到本机磁盘（它是云侧账号数据），不需要本地清理。
- 不确定的技能先别装：技能会影响后续对话的行为，装了不如不装。

## 何时别用

- **只是想复用一段提示词**：先在对话里直接说清楚，稳定了再考虑存成技能。
- **想让它调用外部服务**：那是连接器（MCP）的职责，不是技能。
- **要跨宿主复用同一套能力**：这个 App 的技能是账号内的，换宿主带不走；写成 `SKILL.md` 这类通用格式更划算。

## 已知缺口（未实测，别当成已支持）

| 缺口 | 影响 |
|---|---|
| 上传技能的**文件格式**（压缩包？有没有目录结构要求？） | 不知道能不能直接吃 `SKILL.md` 这种通用格式 |
| 上传后的**生效链路**（何时出现、要不要重启） | 不能承诺"传完就能用" |
| 技能的**版本与更新**机制 | 不确定是否有版本号、能否覆盖升级 |
| 与**对话新建**的技能是否有差异 | 不确定两者是否同一种对象 |
