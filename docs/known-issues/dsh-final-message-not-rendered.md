# [Bug] Web GUI: 助手回复在 thinking / tool call 之后不渲染正文，但状态显示「已完成」

## 环境

| 项 | 值 |
|---|---|
| 应用 | DeepSeek Harness（macOS 桌面应用）|
| 版本 | `0.2.1-rc.2`（build `0.2.1-rc.2`）|
| 界面 | Web GUI |
| 系统 | macOS |
| 会话 | `session-1477e184-67e4-4ff5-bb02-90a5db3f13ae` |
| 时间 | 2026-10-22 03:50 左右（Asia/Shanghai）|

## 现象

一轮助手回复只渲染了前面几类事件：

```text
思考 · The user asks: "所以结果是什么呢" —— so what's the result/outcome?
运行命令 · Check the actual drift between server checkout and cron.d
思考 · # 结果：漂移是真的，而且现在就存在
        ↓
【到这里就停了 —— 最终回答的正文没有出现】
```

而这一轮的状态显示 **「已完成，用时 18 秒」**。

**换句话说：UI 认为这一轮已经正常结束，但用户看到的内容停在「思考」上。**

## 复现

不是每次都有，但在这次会话里连续出现两次：

| 时间 | 用时 | 最后渲染的事件 | 正文 |
|---|---|---|---|
| 03:50（上一轮）| 37 秒 | `思考 · # 你说得对 —— 我用的方式是错的` | ❌ 没出现 |
| 03:50（这一轮）| 18 秒 | `思考 · # 结果：漂移是真的，而且现在就存在` | ❌ 没出现 |

**共同点**：

- 都是**跨多轮工具调用**的一轮（前面跑了 bash 命令，拿到结果后继续）
- 最后的正文都**比较长**（前者约 60 行，后者约 10 行）
- 两次都在 `思考` 块之后直接「完成」，没有正文块

## 期望

一轮「已完成」的回复，应该能看到 **assistant 的最终文本**。

## 实际

只看到 `思考` 与 `运行命令`，最终文本缺失；而 UI 状态是「已完成」。

## 为什么这个特别难发现

```text
「已完成」这个状态是积极的信号 —— 它告诉用户"这轮正常结束了"
        ↓
但内容停在「思考」上，读起来像"AI 在思考但还没说话"
        ↓
用户会以为【是自己没等到】或者【是 AI 卡住了】
        ↓
【而实际上这一轮已经结束、内容也已经产出，只是没渲染出来】
```

**这比"报错"更糟** —— 报错至少知道失败了；这个看起来像成功，但用户拿不到东西。

## 我的猜测（供参考，没有源码无法确认）

按可能性排序：

1. **流式渲染的最后一段 text 没有 flush**
   `thinking` 之后紧接的 text block 可能被当成同一个 block 的延续，而该 block 的渲染路径在「完成」时没有被刷新。

2. **长文本触发了渲染上限**
   两次都是较长的正文。如果存在"单条消息最多渲染 N 行/字符"的限制，超出部分会静默丢弃。

3. **`thinking` 与 `text` 的边界判断有误**
   若最后一段正文被错误归入 `thinking` 类型，而 `thinking` 块在「已完成」后被折叠/隐藏，就会表现成"内容消失"。
