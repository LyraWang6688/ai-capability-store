# scheduled-task —— 触发器是时间的任务

## 一句话

> **定时任务 = 输入 + 处理 + 输出。**
> **输出必须是用户能在界面上看见的地方。**

「定时」只描述了**输入那一端的形状**。一条链能不能用，看的是三件事：
钟响不响、处理跑不跑、**结果到没到用户眼前**。

---

# 一、三段

| 段 | 回答什么 | 现在的形状 |
|---|---|---|
| **① 输入** | 谁在什么时候敲钟 | 服务器 crontab（`scripts/server-timers/timers/*.cron`）· systemd timer · 本机 launchd |
| **② 处理** | 敲完之后做什么 | 可能一段，也可能多段；可能在同一台机器，也可能跨机器 |
| **③ 输出** | **用户在哪看到** | **必须是一个 GUI 位置**：飞书私聊 / 飞书 Base / 飞书文档 / 界面 |

### ⚠️ 「输出」不等于「写了个文件」

```text
写到 /var/lib/ops-audit/reports/2026-10-22.html
        ↓
这不是输出 —— 这是"把结果放在了一个用户不会去的地方"
        ↓
用户能看见的地方 = 手机上打开飞书 / 打开某个网页 / 打开某个客户端
```

**一条链的 ③ 答不上来，它就等于没做完** —— 不管 ① 多准时、② 多成功。

---

# 二、段与段之间：直连 或 桥

**判据只有一条**：

> **A 能不能直接调用 B 提供的接口？**

```text
能   → 直连（同步、即时、请求-响应）
不能 → 桥（A 交给 C 存着，B 自己来取 —— 异步、可能没人取）
```

## ⚠️ 不是「跨环境就要桥」

```text
跨环境只是【可能产生桥】的条件，不是【必然产生桥】。
        ↓
A 和 B 在不同机器上，但只要 A 能调 B 的接口，就是直连。
```

## 现成的直连

| A | B | 走什么接口 |
|---|---|---|
| 服务器 crontab | GitHub Actions | `POST /actions/workflows/<wf>/dispatches` |
| 本机 CLI | 飞书 Base | 飞书 OpenAPI（`lark-cli` 已认证）|
| GitHub Actions | 飞书 Base | 飞书 OpenAPI |
| 任何服务 | 任何有公网 API 的服务 | HTTP |

## 现成的桥

| A | B | 为什么不能直连 | 桥 | 取端是谁 |
|---|---|---|---|---|
| GitHub Actions | **DSH**（本机/常驻）| DSH 没有公网入口，Actions 调不到它 | **飞书消息 + 监听** | DSH 常驻监听 |
| GitHub Actions | **豆包 Work** | 同上 | **飞书消息 + 监听** | 豆包监听 |
| GitHub Actions | 人（不定时来）| 人什么时候来取不可知 | **git 分支** | 人来 `pull` / DSH 来读 |
| 服务器 | 用户本机 | 用户不在线时连不上 | **飞书文件 / git 分支** | 用户打开飞书 / `git pull` |

## 桥的本质是「存转」

```text
直连：A ──请求──> B ──响应──> A        即时要到
桥  ：A ──放──> C         C ──> B       B 什么时候来取都行
        ↓
桥一定有一个"放"的动作 + 一个"取"的动作
        ↓
【所以桥天生异步，也天生可能"放了但没人取"】
```

# 三、两种失败

## ① 桥断了：放了东西，没人取

| 桥 | 断在哪 |
|---|---|
| 飞书消息 + 关键词 | 关键词改了 / 监听没开 → 消息发出去了但没人接 |
| git 分支 | 没人 `pull` → 数据永远停在分支上 |
| 本地文件 | 没人 SSH → 等于没写 |

## ② 缺一段：根本没有「输出」

```text
触发 ✅  处理 ✅  —— 然后就结束了
        ↓
"用户在哪看到"这段压根没设计
        ↓
【比桥断了更难发现：处理成功、日志正常、文件也写了】
```

# 四、检查一条链：四问

```text
① 输入在不在？          cron / systemd / launchd 装了吗、会响吗
② 处理跑不跑？          哪台机器、几个阶段
③ 输出到没到 GUI？      答"文件"就不算
④ 每个不能直连的地方：   桥的「取」端谁负责？有没有人/有没有自动来取
```

**③ 答不上来 → 链没做完。④ 答不上来 → 链会静默失败。**

# 五、关于 `steps`

`registry.yaml` 里每条编排的 `steps` 只写**能指向已登记资产**的那些段。
处理阶段的内部细节（一个 automation 里做了几件事）不拆进 `steps` —— 硬拆会给
每个 `use:` 编一个不存在的路径。

**`steps` 是可校验的落点，上面那段抽象是理解的方式。两者不是一回事。**
