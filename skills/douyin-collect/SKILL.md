# 抖音收录 · 灵感作品

把用户觉得不错的抖音视频，规范化后写进「抖音IP」Base 的「灵感作品」表。

> **一条视频一行，不猜、不编、不重复。**

## 铁律

1. **只写「灵感作品」表**（`tblDGdt1t6RBOM22`）。不碰「关注者」「关注者的作品」「观察结论」。
2. **不改表结构**：不新增字段、不改选项、不改视图。需要新字段就停下来问用户。
3. **不删、不改既有记录**。用户明确要求「更新某条」时才改，且只改被点名的那条。
4. **不编造作者和标题**。只从用户给的分享文案里取；取不到就留空并说明，不要用模型记忆补。
5. **先查重再写**。同一条视频（同 video_id 或同链接）已存在时，**不要写第二行**，告诉用户已收录。

## 工作流

### 1. PARSE — 解析

```bash
python3 scripts/collect.py parse "<用户发来的分享文案或链接>"
```

抖音分享文案的典型形态：

```text
7.43 复制打开抖音，看看【杨迪的作品】#谁还没来学功夫练武术 今天的酒店和服装太适合拍这个了！ https://v.douyin.com/iRabc123/
```

- 作者取自 `【…的作品】`，标题取 `】` 之后、链接之前的文案（保留 # 话题）。
- 短链会尝试还原成 `https://www.douyin.com/video/<id>`；还原失败就沿用原链接。
- **退出码 3 = 只有链接、没有作者和标题**：停下来，请用户转发带「【作者的作品】」的分享文案；不要自己猜。

### 2. CHECK — 查重

```bash
python3 scripts/collect.py check "<同一段文本>"
```

- 退出码 `0`：未收录，继续。
- 退出码 `10`：已收录，把已有记录的「作者 / 作品标题 / 创建时间」告诉用户，**结束，不写**。

### 3. WRITE — 写入

```bash
python3 scripts/collect.py collect "<同一段文本>" --note "<用户说的为什么好；没有就不传>"
```

- 只有用户明确给了「好在哪 / 想借鉴什么」时才传 `--note`，不要替用户编创作灵感。
- 想先看要写什么，加 `--dry-run` 预览。
- 只有链接、用户又坚持收录时，才加 `--allow-blank`。

### 4. VERIFY — 回读

写入后脚本会返回 `record_id` 与 `record_url`。把链接给用户，并复述写入的四个字段。

## 字段映射

| 表字段 | 来源 | 说明 |
|---|---|---|
| `作者` | 分享文案 `【X的作品】` | 原样，不改写 |
| `作品标题` | `】` 之后的文案 | 保留 # 话题，去掉链接和分享尾巴 |
| `参考视频` | 视频规范链接 | 优先 `https://www.douyin.com/video/<id>` |
| `创作灵感` | 用户口述 | 选填；没有就留空 |
| `创建时间` | 系统字段 | 不写 |

## 回复格式

收录成功：

```text
已收录到「灵感作品」：
- 作者：杨迪
- 标题：#谁还没来学功夫练武术 今天的酒店和服装太适合拍这个了
- 创作灵感：转场节奏好
- 记录：<record_url>
```

已存在：

```text
这条已经收录过了：杨迪《#谁还没来学功夫练武术…》，收录于 2026-11-12。
```

## 失败处理

| 退出码 | 含义 | 动作 |
|---|---|---|
| 0 | 成功 / 未重复 | 继续 |
| 2 | lark-cli 调用失败 | 报告错误摘要，不要重试写 |
| 3 | 缺作者与标题 | 请用户补分享文案 |
| 10 | 已收录 | 告知已有记录，不写 |

## 边界

- **一次一条**。用户一次发多条链接时，逐条处理，每条都回读确认。
- **不主动刷抖音找视频**。只在用户给出候选时工作。
- **不做内容分析**。这个 skill 只负责收录；「这条为什么好」由用户说，或由别的 skill 做。
- **不把 Base 坐标发到聊天里**。用户不需要知道 token。

## 依赖状态

`lark-cli` 目前未在 `external-capabilities/registry.yaml` 登记，因此不声明依赖；这与 `repo-collector` 的处理一致。
