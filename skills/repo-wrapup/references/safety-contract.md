# 安全契约 · 什么能删，什么不能删

> 这份文件的目的是**让「该不该删」变成机械判断**，不需要 agent 自己权衡。

## 一、可以安全删除（三条全中）

`safe_cleanup.sh` 的判定条件，缺一不可：

| # | 条件 | 检查方式 |
|---|---|---|
| 1 | **已推送** | 有上游且 `upstream..branch` 提交数为 0；无上游时 `base..branch` 为 0 |
| 2 | **已合并** | 出现在 `git branch --merged <base>` 里 |
| 3 | **未被占用** | 不是当前分支；不在 `git worktree list` 的 branch 列表里 |

三条同时满足 → 进「可安全删除」候选。

## 二、绝对不能删（硬禁止）

| 对象 | 原因 |
|---|---|
| 当前分支 | 会把自己所在的分支删掉 |
| `main` / `master` | 主干 |
| 含未推送提交的分支 | **会丢工作** |
| 被 worktree 占用的分支 | 那个 worktree 可能正被别的 agent 使用 |
| 别人的 worktree | 误删不可逆；不确定就留 |
| 有任何未提交改动的 worktree | 同上 |

## 三、worktree 为什么一律不自动删

三个理由：

1. **可能有未提交改动** —— 一旦移除，改动就没了
2. **可能正被另一个 agent 使用** —— 多 agent 并行时分不清
3. **移除是本地操作，没有远端副本可恢复**

> 所以 `safe_cleanup.sh` **只报告 worktree，不删除**。
> 需要清理时，由人判断后手动执行 `git worktree remove <path>`。

## 四、误删的后果比留垃圾严重

这是本契约的总原则：

```
留一个多余的分支   → 下次还能删
误删一个有活的分支 → 工作没了
```

**所以所有边界情况一律「不删，报告」。**

## 五、示例：一次典型判断

```
分支 feat/foo
  ├─ 已推送？      是（无 ahead 提交）
  ├─ 已合并？      是（--merged 命中）
  ├─ 被占用？      否（不在 worktree 列表）
  └─ 结论：可删除 ✅
```

```
分支 fix/bar
  ├─ 已推送？      否（ahead 3 个提交）
  └─ 结论：跳过 ❌ → 列入「含未推送提交 · 不删」
```

```
worktree /path/to/wt  [chore/baz]
  └─ 结论：一律只报告，不删除 ⚠️
```
