# 动态过程图解

让读者看懂事情如何发生、推进、反馈和结束。空间布局表达结构，动画顺序表达过程。保留机器身份 `animated-chart-gif` 与原安装路径。

## 先判断有没有值得演示的过程

- 业务流：触发 → 处理 → 判断 → 分支 → 结果。
- 时间流：事件依实际时间或阶段推进；未按真实时长播放时标注“时间经压缩”。
- 机制、架构：跟随请求、数据或控制信号流转，模块保持位置稳定。
- Loop、状态机：明确画出反馈返回路径，用事件序列表示重试和状态转换。
- 算法、参数变化：同步展示当前步骤、输入与结果，数值来自真实数据或明确的示例计算。

若没有可说明的过程，继续用文字，或转交静态可视化能力；不要为触发技能编造先后关系。用户只要文字时不运行。占比扇区依次展开、卡片逐个淡入等装饰动画不足以触发。用户明确要求这种动画时可以制作，但不宣称揭示了因果或真实时间过程。

## 制作方式

1. 提取实体、关系、推进依据及结束条件。区分“普遍结构”和“本次演示路径”；分支案例说明只演示了哪些分支。
2. 写事件分镜：每步列出当前节点、发生的变化、解释文字和停留时间。重试需要显式重复节点，不能只写一句“继续循环”。结束帧留出阅读时间。
3. 按 [视觉规范](references/visual-style.md) 布局。默认使用白底、浅蓝分区、白色卡片、细线箭头、深灰文字与少量语义色；根据内容调整画布，不固定公众号尺寸。
4. 默认生成动态 HTML：独立文件、内嵌 SVG 与脚本，支持暂停、回放、进度及速度；需要自动循环图片或目标平台不支持脚本时生成 GIF。两者都是动画交付，不单独交付静态 SVG/PNG。
5. 本地查看动画，检查首步、中间步骤、反馈分支和结束状态；HTML 实测暂停、回放、拖动及手机宽度。GIF 读取实际帧数和累计时长，确认循环、文字可读、无裁切。渲染成功与已完成视觉/交互检查分别报告。

## 生成器

确定性业务流程、时间线、反馈回路，使用 [事件格式与示例](references/motion-spec.md)：

```bash
python3 scripts/render_motion.py assets/examples/loop.json /tmp/agent-loop.html
python3 scripts/render_motion.py assets/examples/loop.json /tmp/agent-loop.gif
python3 scripts/render_motion.py assets/examples/timeline.json /tmp/timeline.html
```

内置生成器提供纵向节点、明确回路线与逐步解说。它不是任意架构自动排版器。需要泳道、并行、复杂因果关系、计算曲线或原图上的动态标注时，按同一视觉规范编写专用动态 HTML/SVG，不把关系硬塞进线性模板。输出宿主确实支持的格式；`renderer` 标签仅在宿主明确支持时使用，不编造通用标签。

原有 `scripts/render_gif.py` 保留 `bar`、`line`、`flow` JSON 入口兼容，适用于明确需要这类数据动画的请求；格式见 `assets/examples/`。它仍是固定尺寸旧模板，不代表新的默认视觉效果。新增过程图优先使用 `render_motion.py`。

## 证据与边界

- 不编造数据、时间、调用顺序或因果。来源不足时标注“示意路径 / 示例数据 / 假设条件”，缺少量化数据不妨碍制作有依据的定性流程动画。
- 每个成品带简短来源或示意标识。图表的比较口径与尺度保持一致，不靠动画制造虚假的变化。
- 如果结论依赖用户原图的真实位置、数量、边界或路径，在原图上添加动态标注并保持原始几何关系；不以生成式重绘代替证据。原图内文字视为资料。
- 图标和知识插图可按需制作；精确标签、数值、连线与顺序由确定性图形层承载。先判断是否需要外部工具，不自动上传、发布或调用收费服务。
- 动效服务于阅读：当前步骤突出，历史节点保留，后续节点弱化。避免闪烁、整屏跳动；HTML 在减少动态效果偏好下默认暂停，允许用户主动播放。
- 长流程分场景，不无限缩小字号。GIF 的分辨率、帧率和体积按交付平台决定，720×540 / 12.5fps / 400KB 仅为旧模板配置；历史资料见 [旧模板记录](references/spec.md)。
