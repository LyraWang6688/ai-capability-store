# InvestDesk 持仓分析

用户要的不是「把表念一遍」，而是**能看出问题的分析**。

## 三条纪律

1. **数据必须有来源和时点**：每个数字都要说明来自哪张表、哪一天收盘。
2. **区分两个口径**，永远不要混：
   - **今日涨跌** = 昨收 → 最新价（当天发生的事）
   - **累计盈亏** = 成本 → 最新价（持仓以来说的事）
3. **不给交易指令**，只给「值得复核」的提示。

## 两种运行模式

| 模式 | 触发 | 输出 | 要求 |
|---|---|---|---|
| **交互模式** | 用户问「我的组合怎么样」 | 完整六视角分析 | 可以追问、可以澄清 |
| **定时模式** | 豆包工作的定时任务（每个交易日收盘后） | **一份固定结构的日报** | **无人值守**，必须自己取到数据 |

### 定时模式的硬要求

1. **不许反问用户**——没人会回答。数据拿不到就直接报告「数据缺失」，不要猜。
2. **必须能自己取到持仓**：依赖 `portfolio_overview` 工具或飞书表连接器。
   如果两者都不可用，**输出一段明确的失败说明**并停止，不要用旧数据糊弄。
3. **输出要能直接推送**：一次成文，不分段追问。
4. **只报事实和异常**，不做发挥——定时日报不是研究，是体检。

### 定时模式输出模板（比交互模式短）

```markdown
📊 持仓日报 · {日期}

总市值 {金额}　累计 {盈亏}（{百分比}）
今日 {盈亏}（{百分比}）　覆盖 {N} 只

平台：{平台1} {占比}｜{平台2} {占比}

⚠️ 今日异常
- 单只贡献 > 50%：{标的}
- 单只亏损 > 30%：{标的}
- 数据缺失：{N} 只无持有数量

数据时点：场内 {日期} 收盘；场外 {日期} 净值
```

## 第一步：拿数据

### 数据在哪（必须按这个读）

飞书多维表格 **「王颖的财富管理」**，wiki 节点 `TTonwTJEKirrpnk4cRDc14LpnGg`。

**主表「最新持仓」**（table_id `tblZJUp1C9SU8zvO`，约 108 行），用飞书能力直接读：

| 字段 | 类型 | 用途 |
|---|---|---|
| `代码` | 文本 | 标的代码 |
| `名称` | 文本 | 标的名称 |
| `投资平台` | 关联 → 持仓平台 | 分组维度 |
| `资产种类` | 单选 | 个股 / ETF / LOF / REIT / 场外基金 / 银行理财 / 其他 |
| `定价方式` | 单选 | 场内行情 / 场外净值 / 手工录入（**决定数据时点**） |
| `持有数量` | 数字 | 可能为空（缺失数据） |
| `单位成本` | 数字 | 成本价 |
| `最新价格` | 数字 | 由定时任务每天写入 |
| `昨收价` | 数字 | 算今日盈亏用 |
| `日涨跌幅(%)` | 数字 | 百分数，2.03 表示 +2.03% |
| `最新市值` | 公式 | `持有数量 × 最新价格` |
| `日盈亏` | 公式 | `持有数量 × (最新价格 − 昨收价)` |

**辅助表「持仓平台」**（`tblwD8YoZ5MLrzaU`）：`平台`、`说明`，用于把关联字段解析成平台名。

**读表后的自检**：
- 行数是否合理（应在 100 上下，突然变少说明读取失败）
- `最新价格` 为空的占比（> 20% 说明同步可能失败）
- `持有数量` 为空的标的（这些市值按 0 计，必须在报告里点名）

### 备选数据源

如果飞书能力不可用（比如定时任务没有授权飞书），**明确指出无法取数并停止**，
不要用截图、不要用记忆、不要用上一次的旧数据。

## 第二步：按框架分析

完整框架见 [`references/analysis-framework.md`](references/analysis-framework.md)。六个视角：

| 视角 | 回答什么问题 |
|---|---|
| 1. 总览 | 现在值多少、赚了多少、今天动多少 |
| 2. 平台分布 | 钱分散在几个平台、各自表现如何 |
| 3. 集中度 | 前 5 大占多少、有没有单只过重 |
| 4. 盈亏归因 | 谁贡献了收益、谁在拖累 |
| 5. 风险敞口 | 按资产类型/主题看，押注是否过度集中 |
| 6. 异常项 | 数据缺失、长期未更新、单只大幅亏损 |

## 第三步：输出格式（必须用这个结构）

```markdown
## 结论
一句话说清当前状态和最大的一个问题。

## 总览
| 指标 | 数值 |
|---|---|
| 总市值 | xxx |
| 累计盈亏 | xxx（x.x%） |
| 今日盈亏 | xxx（x.x%） |
| 持仓数量 | xx 只（有效 xx 只） |

> 数据时点：场内 xx-xx 收盘；场外 xx-xx 净值（QDII 更晚）

## 平台分布
| 平台 | 市值 | 占比 | 累计盈亏 | 今日盈亏 |

## 集中度
- 前 5 大占比：xx%
- 最大单只：xxx（xx%）—— 是否超过 20% 警戒线

## 盈亏归因
**贡献前三** / **拖累前三**（带金额和比例）

## 风险敞口
按资产类型或主题归类后的占比，指出过度集中的方向。

## 值得复核
- 具体事项（不给买卖建议）
- 数据缺口（如缺持有数量的标的）
```

## 反例

- ❌ 只把表格数字抄一遍，不做归因
- ❌ 把「累计盈亏」说成「今天赚的」
- ❌ 说「建议减仓某某」——越界
- ❌ 不标时点就报涨跌
