# AI 工具足迹与实践传播

目标是让读者相信用户确实用过 AI 工具，并理解其投入、成果和经验。完整交付为公众号文章、适配的可视化 HTML 和内部证据底稿；采集服务于传播主题。仅要求盘点或补数据时，按用户指定范围交付。

## 先确定主题与已有进度

从请求和已有材料确定读者、传播主题、叙事区间。默认面向对 AI 实践感兴趣的公众号读者，以具体经历和成果展示能力；可推断的信息直接采用，不必先做问卷。

先寻找已有底稿和采集状态，包括用户给出的归档目录。归档位置本身不表示材料失效。用户未指定时，把长期材料放在本次工作区 `ai-footprint/`；后续若位置不明，先搜索已知工作区的 `state.json`，不要静默另起历史。多个底稿无法判断归属时再询问。

**采集区间与叙事区间分别记录**：
- 首次：尽可能追溯到 2024 年或更早；不把 2024 年设为下限，实际覆盖以来源为准。
- 后续：每个来源从上次成功截止点继续，到本次启动时固定的截止时间。允许小范围重叠并去重，避免边界遗漏。
- 写作：可只讲新增一个月，也可调用累计材料讲完整历程；不为写长期回顾重复全量扫描。
- 新发现的旧材料按实际事件日期补入，保留本次发现时间。

采集前必读 [增量与底稿规则](references/collection-state.md)。

## 采集与积累

按主题收集三类素材：使用痕迹（会话、访问、付费等）、实际成果（作品、项目、工作流、可核验结果）、个人经验（本人回忆、同期笔记或对话）。默认先读元数据，需要支撑具体案例时才聚焦阅读相关内容。

采集前读 [证据来源与口径](references/evidence-sources.md)。来源只读；数据库使用一致性快照；不提取密码、Cookie 值、令牌或无关邮件正文，不联网登录账号。当前请求不授权对外发布或发送。

每个来源独立保存状态、覆盖范围和失败原因。无权限、解析失败、未找到、未采集不等于零使用。只在该来源本次范围完整采集并写入底稿后推进进度；截断不能当作完成。

现有 `scripts/collect_evidence.py` 是**全量辅助扫描器**，只有文件 mtime、Chrome Default 历史和部分邮箱等痕迹；不解析有效会话、不统计 Screen Time、不支持区间参数或自动推进进度。仅在首次或明确补查时选择使用；增量应针对来源按事件时间查询并维护状态，不得每次运行该脚本再过滤输出冒充增量。首次也可按来源直接采集，不要求运行该脚本。

```bash
python3 scripts/collect_evidence.py --out run-evidence.json
python3 scripts/draw_timeline.py run-evidence.json --out footprint.png
```

辅助扫描输出不自动成为正式累计底稿；先核对口径、来源完整性与证据，再归档。旧版 `paid` 字段未经核验不作为付款证据。图仅是可选素材，不替代文章和 HTML。

## 从素材到传播内容

按 [写作与交付](references/storytelling-deliverables.md) 选择主题、案例并创作。

1. 挑出能服务主题的故事：具体场景 → 做了什么 → 得到什么 → 证据 → 经验。工具数量和使用规模建立可信度，代表成果体现能力。
2. 关键事实、数字关联证据编号；区分观察、推断、用户自述。不能从时间线编造动机或第一人称感受。
3. 写公众号文章：推荐与备选标题、摘要、正文及视觉位置。阶段和转折由材料决定，不强凑迁移路线或反直觉发现。
4. 生成配套可视化 HTML：默认用于公众号正文，手机友好，关键内容不依赖 JavaScript。实际排版时，如可用，读取 `wechat-html-css-layout` 技能并沿用“要AI不释手”规范；不可用时按本技能交付要求完成。独立交互网页仅在用户需要时增加。
5. 渲染检查 HTML 的移动端阅读、图表标签和溢出；核对图文数字与脱敏。保存文章主题、所用证据、采集截止与成稿/发布日期；不把成稿记成已发布。

持久底稿与当次成品分别保存。遵守当前环境输出目录约定，不把个人采集数据写入技能安装目录。交付时说明本次新增范围、失败或待补来源、产物位置；无需在公开文章中展开全部技术限制。

面试用途另读 [面试叙事](references/interview-narrative.md)。
