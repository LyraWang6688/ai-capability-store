# 把足迹变成面试叙事

足迹是**素材**，面试要的是**判断力**。同一个数据，讲法决定含金量。

## 1. 三个能撑住追问的故事（按含金量排序）

| 故事 | 证据锚点 | 面试官会追问 |
|---|---|---|
| **迁移判断**：若材料确有从订阅制到 API 或自建 Harness 的迁移，每次都说明"为什么换、换的代价是什么" | 订阅邮件起止 + API 开通记录 + 本地工具活跃曲线 | 迁移的触发点是什么？有没有换回来过？ |
| **成本意识**：算清单个工具的月度成本与产出，砍掉不划算的订阅 | 账单金额、退订记录 | 你怎么衡量"值不值"？ |
| **长期投入**：某个工具连续订阅 12 个月，期间有版本迭代与计费方式变化 | 逐月已核验的订阅或付款记录（续费提醒不能证明扣款） | 这么长时间里你做了什么？ |

## 2. 叙事模板（一句话 - 证据 - 反思）

```
我试过 N 个 AI 工具，为其中 K 个付过费（总跨度 X 个月）。
使用演进：<按证据填写；允许多工具并用，无迁移则不写迁移>
转折点：<日期与原因>
我学到的：<一句方法论>
```

## 3. 面试官真正在测什么

- **不是**"你用过多少工具"（谁都能列）
- **是**：你怎么评估工具、怎么迁移、怎么控制成本、怎么把工具变成产出

把「工具清单」升级为「**决策清单 + 产出清单**」：

| 层级 | 弱 | 强 |
|---|---|---|
| 工具 | 我用过 14 个 AI 工具 | 我连续订阅 Trae 12 个月，在它转向 token 计费时开始评估替代 |
| 成本 | 我付过几个订阅 | 我把订阅预算从固定月费迁到按量 API，用缓存命中把单价压下来 |
| 产出 | 我让 AI 帮我写代码 | 我交付了 X 个可验证的东西（仓库/包/文档/自动化），每个都有证据 |

## 4. 三条纪律

1. **每个数字都要能指出出处**（邮件、账单、文件路径、会话计数）——被追问时当场能给。
2. **不要把"付费"说成"深度使用"**；也不要把"浏览过付费页"说成"付过费"。
3. **主动说边界**："这是本机留下的痕迹，不代表全部"——这反而显得可信。
