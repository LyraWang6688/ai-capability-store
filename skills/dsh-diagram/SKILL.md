# 对话内卡片图

一句话：**你写 JSON，插件画卡片。** 渲染由 `diagram-card` 插件完成，本 Skill 只负责「该不该画」和「怎么写」。

## 先判断值不值得画

值得画（至少满足两条）：

- **有层级**：一个外部容器里套着若干并列项。
- **有推进**：步骤按顺序发生，或存在回环。
- **有分类**：4~6 个并列概念需要一眼分清。
- **能省字**：图能替代三段以上的文字说明。

不该画：

- 纯列表，或步骤少于 3 步。
- 数据趋势、占比、数值对比——那是表格和图表的活，卡片图画不了坐标轴。
- 短回答（一两句话能说完）。
- 只是在复述正文：图要补充文字没说清的关系，不是把段落搬进格子。
- **同一段回复已经画过一张**。

判断不画就用文字或表格。**不要为了触发而编造层级。**

## 两种模板

| 模板 | 什么时候用 | 结构 |
|---|---|---|
| `layered` | 分层结构：外部任务 → 中间一层能力/模块 → 产出 | 顶部胶囊 → 分组容器（标题 + 层名 + 等宽卡片网格）→ 底部结果 |
| `flow` | 有先后顺序、可能回环的过程 | 起点胶囊 → 编号步骤 → 回环说明 → 终点 |

完整字段见 [spec.md](references/spec.md)，可直接改的样例见 [examples](assets/examples)。

## 四条硬约束

1. **JSON 必须合法。** 解析失败插件不渲染，读者会看到你写的原始代码块——比不画更糟。发送前自己确认：没有尾逗号、引号成对、没有注释。
2. **一张图最多 6 张卡片。** 超过就拆成两张图，或改用表格。文案上限：英文 ≤ 14 字符、中文 ≤ 10 字。
3. **一段回复最多一张图。** 第二张开始只增加滚动，不增加理解。
4. **图标只写清单里的名字。** 写错不会报错，图标会静默消失——比不写更难看。

## 图标清单

`user` · `brain` · `book` · `tools` · `loop` · `shield` · `clipboard` · `database` · `check` · `arrow`

语义参考：`user` 人/任务 · `brain` 模型/推理 · `book` 知识/上下文 · `tools` 工具/执行 · `loop` 循环/重试 · `shield` 权限/安全 · `clipboard` 校验/记录 · `database` 存储/状态 · `check` 结果/完成 · `arrow` 连接（模板已自带，一般不手写）。

## 发送前校验

```bash
python3 scripts/check_spec.py <your-spec.json>
```

检查字段类型、图标名、卡片数量、文案长度。**不通过就别发。**

## 边界

- **只在装了 diagram-card 的 DSH 里用。** Claude / ChatGPT / 普通文档里它会显示成一段 JSON。
- **不是数据图表工具。** 不做趋势、占比、多轴对比；那些交给表格或 `animated-chart-gif`。
- **不编造结构。** 层级和顺序必须来自真实内容；拿不准就少画。
- 深色/浅色由宿主自动适配，**不要在 JSON 里写颜色**。
