# 内容审阅准则

以下是编辑判断维度，不是搜索平台公布的排序因子。只检查与当前内容相关的项目；不适用就说明，不要求每篇文章包含所有模块。

| 维度 | 如何判断 | 有价值的修改 | 常见误判 |
|---|---|---|---|
| 主题与问题 | 标题、开头与正文是否围绕同一个问题；读者能否说明文章具体讲什么 | 标题补充必要对象；开头交代场景与关键信息 | 所有故事都必须首段给完整答案；用热门关键词替换真实主题 |
| 实体与概念 | 工具、平台、主体与代词是否清楚；专业词是否需要简短解释 | 首次出现给够上下文；说明同名词在本文的含义 | 反复堆全称；解释读者已熟悉的每个词 |
| 回应与因果 | 文章有没有解释为什么、怎么做；因果是否有材料支持 | 补足前提、机制和过程；区分个人动机与推断 | 从时间先后推出因果；把个例改写成普遍定律 |
| 可摘引性 | 关键结论离开相邻段落后，是否仍能识别主体、条件与范围 | 在关键段落补必要指代和限制；保留清楚的概括句 | 每段都强行独立；重复结论以增加频次；把小标题机械改成问句 |
| 证据与归属 | 数字、引用、成果、建议是否对应适当来源；事实和观点是否区分 | 纠正过度承诺；补直接支持说法的来源；注明数据时点 | 用参考链接装饰权威；把代码存在当成功运行；编造个人经历 |
| 适用条件 | 结论在哪些条件下成立，有什么重要例外 | 给出必要边界与反例；指出混合处理方式 | 把所有潜在风险堆成免责声明；为每句话增加保留措辞 |
| 阅读与文本可访问 | 段落长度、层级、图文关系是否适合媒介；关键内容有无文字 | 用自然段、必要列表或图表降低理解成本 | FAQ、列表、表格越多越好；为了机器把文章写成字段清单 |
| 信息增量 | 内容有无具体经历、可复核过程、独特解释或可用方法 | 用真实案例支撑判断；删掉空泛重复 | 强制加入“独家”观点、资历或未经证实的量化收益 |

## 问题记录

每个实质问题应包含：原文位置或短引文 → 影响理解/准确性的原因 → 建议改法 → 所依据材料或待核验事实。用“优先修复 / 建议改进”表达先后；不要制造伪精确分数。

审阅结论可使用：具备内容基础 / 有关键问题待修 / 材料不足以判断。单项可标为：已满足 / 待改进 / 无法判断 / 不适用，后面附具体依据。

## 最后一次核对

从修订稿挑出主要结论，检查单独概括时是否仍保留主体与条件。确认删改没有把“测试中”变成“已上线稳定”、把“一次观察”变成“长期效果”、把“我的配置”变成“所有工具”。不要求为短文另写整份报告。
