# 收录文案标准

三段叙事文案（`项目简介` / `核心亮点` / `参考价值`）是这个表的价值所在。
写得好，半年后一眼能决定要不要重新看；写得差，就是一堆链接。
**照抄下面的标准，不要自由发挥。**

## 三段各回答一个问题

| 字段 | 回答的问题 | 不该出现 |
|---|---|---|
| `项目简介` | 它**是什么**？ | 评价、形容词堆砌 |
| `核心亮点` | 它的**机制**有什么值得看？ | 营销词（"强大"、"领先"、"一站式"） |
| `参考价值` | 对**我自己的 Store** 意味着什么？ | 泛泛的"值得学习" |

## 硬标准

1. **一句话原则** — 每段 1–2 句，用分号/顿号并列具体要素，不写小作文。
2. **具体压过抽象** — 写"基于 RFC 8615 的 `/.well-known/agent-skills/index.json`"，不写"有标准的发现机制"。
3. **`核心亮点` 必须可验证** — 任何一条都能在仓库里找到对应物。做不到就别写。
4. **`参考价值` 必须带判断** — 不只有"要学什么"，也要有"哪里不能照搬"。只夸不批的记录没有决策价值。
5. **不写 Stars 之外的数字** — 混淆指标（趋势、增长）没有事实来源，禁止编造。
6. **保留英文专有名词** — `npx skills`、`SKILL.md`、`well-known URI` 不翻译。

## 真实范例（表内既有记录，作为风格基线）

**vercel-labs/skills**

> 项目简介 — 开放 Agent Skill 生态的通用命令行工具（`npx skills`），负责 Skill 的发现、安装、更新与跨 Agent 投放。
>
> 核心亮点 — `add/use/find/update/remove/init` 全套命令；自动适配 Claude Code、Codex、Cursor、Gemini CLI 等 80+ Agent；支持项目/全局作用域、软链共享一份原件、私有仓库认证；配套 skills.sh 发现站。
>
> 参考价值 — 个人 Skill Store 的安装器无需自研，让商店成为它的一个可解析源即可。

**ricable/Agents-cli**（注意最后一段的"负面判断"）

> 项目简介 — "Agent 所用 CLI 工具的包管理器"，集工具安装、Skill 工厂、插件生成与 MCP 桥接于一体。
>
> 核心亮点 — 从 GitHub/npm/PyPI/crates.io 安装并递归探测 `--help` 提取命令树；自动生成 `SKILL.md` 与完整 Claude 插件（hooks、多 Agent、斜杠命令、市场）；MCP 暴露；lockfile；SaaS UI。
>
> 参考价值 — 参考"CLI 工具→命令树→Skill 自动生成"流水线；整体功能面过大、实验性强，不宜整体照搬。

## 反例

| ❌ 差 | ✅ 好 |
|---|---|
| 一个非常强大的 Agent 工具 | 开放 Agent Skill 生态的通用命令行工具（`npx skills`） |
| 支持很多 Agent | 自动适配 Claude Code、Codex、Cursor 等 80+ Agent |
| 值得学习其架构设计 | 参考"CLI 工具→命令树→Skill 自动生成"流水线；整体不宜照搬 |

## `跟进状态` 怎么定

这是**用户的处置意图**，不是项目评分：

| 值 | 含义 |
|---|---|
| 待深入 | 还没细看，先存着 |
| 参考中 | 正在对照它做设计决策 |
| 已借鉴 | 已经真的用进自己的项目 |
| 仅收藏 | 有意思但和当前方向无关 |

不确定就填 `待深入`，**不要替用户拔高到「已借鉴」**。
