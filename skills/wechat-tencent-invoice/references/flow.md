# 腾讯充值开票 · 12 步细节与踩坑

> 来源：2026-10-25 在本机微信桌面版上真实走通一次（3 笔微信支付订单合并开 1 张普通发票，57.00 元）。
> 界面层面的事实（窗口归属、权限、AX 能力）见 Store 里的 computer-automation 界面档案（重构前 `computer-automation/computer-use/wechat-macos/`，重构后 `orchestrations/computer-automation/wechat-tencent-invoice/README.md`）；
> 本文只写「怎么一步步点过去、每步看什么」。

## 0. 前置检查

```bash
scripts/build.sh            # 产出 scripts/ui（一次即可）
scripts/ui status           # axTrusted=true 才会有点击；front= 当前前台 app
scripts/ui windows wechat   # 微信窗口清单：id / name / bounds / onscreen
```

判断标准：

- `axTrusted=false` → 合成点击**静默无效**，页面不动，先解决辅助功能授权；
- 截图全黑 → 缺屏幕录制授权；
- 只有 `Weixin` 没有 `腾讯充值` → 小程序还没打开，从第 2 步开始。

## 1. 坐标怎么算（唯一正确做法）

**不要用 `shotwin` 的图算点击坐标**：`screencapture -l` 会把窗口阴影一起截进来，阴影宽度随窗口尺寸变化（实测 46～112 px），换算必错。

用区域截图，坐标系就是点数、像素是 2 倍，没有偏移：

```bash
scripts/ui shotregion <x> <y> <w> <h> /tmp/r.png
scripts/ui ocr /tmp/r.png        # 输出 "x,y,w,h<TAB>文字"，像素坐标
# 全局点 = 区域原点 + OCR像素 / scale（scale 由 shotregion 打印）
```

页面里找不到文字锚点时，才退化为「窗口 bounds + 窗口内相对比例」。比例要现场量，不要记死。

### 1.1 OCR 不可用时的降级

本机实测：Vision 文字识别对**新编译的二进制**报 `TextRecognition.CRImageReaderError`（旧二进制正常），原因未查明。降级做法：

1. 用 `shotregion` 截包含目标文字的区域；
2. 让会看图的模型直接读图，说出目标文字在图片里的像素位置；
3. `全局点 = 区域原点 + 像素/2`。

这条降级路径在本轮实操里用过多次（比 OCR 更慢，但不受系统 OCR 影响）。

## 2. 打开小程序

- 微信主窗口搜索框输入「腾讯充值」→ 回车。
- 观察点：出现独立窗口，`name=腾讯充值`；窗口截图里有「电子发票开具成功通知」卡片与底部三个 tab。
- 坑：搜索框粘贴后如果结果面板不出现，等 2 秒或再回一次车；`open -a WeChat` 会把**主窗口**抬到最前，可能要再点一次主窗口搜索框。

## 3. 我的帐户

- 点底部第三个 tab「我的帐户」。
- 观察点：弹出一列：我的余额 / 充值记录 / 续费管理 / 积分兑换 / **申请发票**。
- 坑：第一次点击常常只用于把窗口变成 key window，被吞掉。先 `ui focuswin <pid> 腾讯充值` 再点；点完必须截图确认菜单出现。

## 4. 申请发票

- 点菜单里的「申请发票」。
- 观察点：微信内置浏览器窗口打开，`name` 以「如何申请发票？ - 腾讯客服」开头。
- 坑：这个动作会新开/复用内置浏览器窗口，窗口位置可能落在主窗口下面——用 `ui windows wechat` 拿 id 后 `ui focuswin <pid> "WeChat (Window)"`。

## 5. 普通发票入口（最容易点错的一步）

页面底部两行，只差一行、y 相差约 20 点：

```text
开具增值税普通发票，请点击（申请入口）        ← 要这个
如您是受公司委托采购，需开具增值税专用发票，请点击（申请入口）
```

- 用 OCR 找到含「开具增值税普通发票」那一行的框，点它**末尾**（「（申请入口）」处）。
- 观察点：进入微信授权页（头像 + 「您当前登录账号为微信号」+ 蓝色「申请发票」+ 白色「开票记录」）。
- 坑：点错会进《开具增值税专用发票须知》（要营业执照复印件与开票声明）。浏览器后退即可，不要在专用发票页继续。

## 6. 选订单

- 点「申请发票」→ 页面标题变「申请发票」，出现「请选择申请发票订单」、右上「最近三个月订单」。
- 左侧复选框逐笔勾选。
- 观察点：底部「总价：¥xx.00」累加；「下一步」从灰变蓝。
- 坑：复选框在行文字左侧约 23 点；点文字本身不勾选。

## 7. 抬头类型

- 「下一步」→「请选择抬头类型：个人 / 组织 / 公司」，默认选中「个人」，提交按钮是灰的。
- 高校 / 事业单位 / 公司报销 → 选「组织」。
- 观察点：表单出现只读三行（发票主体 = 深圳市腾讯计算机系统有限公司、发票项目、发票金额）+ 两个输入框。

## 8. 填抬头与税号

- 输入项：`*发票抬头名称`、`统一社会信用代码`。
- **必须点中占位符文字本身**（`请填写发票抬头` / `请填写统一社会信用代码`），偏上约 20 点会点空、粘贴进不了框。
- 中文用 `ui paste <text>`（pbcopy + ⌘V）；逐字键入对微信网页不稳。
- 观察点：点击后截图能看到光标；粘贴后再截一张，确认框里出现文字、且「提交」变蓝。
- 坑：`⌘A` 再粘贴可以覆盖残留文字（先试填时留下的测试串要走这一步清掉）。

## 9. 提交前必须停下

把以下五项念给用户，等明确「确认提交」：

1. 勾选了几笔订单、分别是哪几个月；
2. 金额合计；
3. 发票类型（电子发票 / 增值税普通发票）；
4. 发票抬头；
5. 统一社会信用代码。

发票提交后**平台不允许修改**，错了只能找客服。

## 10. 提交

- 点「提交」→ 弹窗「发票申请提交后不可修改，请确认内容无误后再提交」→ 点「确认」。
- 观察点：出现「申请成功 / 您提交的开票申请已受理」，并写明普通发票约 5 个工作日处理、可在「开票记录」查看、也会收到【腾讯充值】公众号提醒。
- 坑：弹窗按钮是「取消 / 确认」，不要点成取消；确认后不要重复点提交（会怀疑是否成功→再看记录即可）。

## 11. 核对

- 回「申请发票 / 开票记录」页 → 点「开票记录」。
- 观察点：列表第一行是**新单**，金额一致、状态「开票中」、有开票单号；旧单显示「已开票」。
- 把开票单号报给用户，作为「已提交」的可核对凭据。

## 12. 收尾

- 关掉内置浏览器窗口（会残留多个 tab）；
- 恢复被 `minwin` 最小化的宿主窗口；
- 小程序窗口可以留着（下次还要用）。

## 结构性风险（写进脚本前必读）

- **静默失效**：微信改版后按钮位置变、文字不变，OCR 还能找到但对不上；所以每一步都要「观察点 + 失败即停」，不能连环点。
- **不要写死坐标做定时任务**：窗口每次重排都会变。真要自动化，定位必须走 OCR + 失败非零退出。
- **平台可能有 trusted gesture 检查**：这次实测没有被拦，但换页面/换版本要重新确认（弹窗、新窗口类动作最可疑）。
- 开票是一次外部不可逆动作：无人确认时永远停在提交前。
