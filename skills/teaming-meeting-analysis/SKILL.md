# 组队会议动力分析

对一场**已结束的**飞书会议做团队动力分析，产出四部分报告：
团队状态定位、互动概览、未完成的对话与非共识、给领导者的建议。

**这是观察工具，不是考核工具。**

## 什么时候用 / 不要用

| 用 | 不要用 |
|---|---|
| 「分析这场会」「看看这场会的团队氛围」 | 「帮我整理会议纪要」「提取待办」 |
| 「这场会复盘一下」「团队协作状态怎么样」 | 「这场会讲了什么」（摘要类需求） |
| 定时任务：发现新妙记就自动分析并汇报 | 「查一下我明天的日程」 |
| | 评价某个人（**明确不支持**） |

## 准备：拿到 host token（每个用户只做一次）

凭证会**保存在本地文件**里，所以只问一次。

### 第一步：先看本地有没有存好的凭证

```bash
TOKEN_FILE="$HOME/.teaming-mcp/host-token"
if [ -s "$TOKEN_FILE" ]; then
  echo "已有凭证，可直接使用"
else
  echo "需要获取凭证"
fi
```

**有就直接用，跳到「标准流程」。** 不要重复问用户。

### 第二步：没有就问用户要接入码

**不要自己猜、不要到处翻找。** 从环境变量、历史文件或记忆里翻出来的凭证
**可能是别人的**——用了会把报告归到别人名下。直接问用户：

> 这个分析需要一个 8 位接入码（形如 `ABCD2345`），是管理员单独发给你的。
> 你手上有吗？没有的话我告诉你去哪要。

**拿到码之前不要往下走。**

### 第三步：用码换凭证并保存

```bash
mkdir -p "$HOME/.teaming-mcp"
TOKEN=$(curl -s -X POST https://meeting.bamamei.online/api/host/v1/enroll \
  -H 'Content-Type: application/json' \
  -d '{"code":"<用户给的接入码>"}' \
  | python3 -c "import sys,json; print(json.load(sys.stdin)['hostToken'])")

printf '%s' "$TOKEN" > "$HOME/.teaming-mcp/host-token"
chmod 600 "$HOME/.teaming-mcp/host-token"
echo "凭证已保存到 $HOME/.teaming-mcp/host-token"
```

保存后告诉用户：**「凭证已就绪，以后不用再提供接入码了。」**

### 之后每次分析

```bash
TOKEN=$(cat "$HOME/.teaming-mcp/host-token")
```

拿它做后续请求的 `Authorization: Bearer $TOKEN`。

> ⚠️ **如果运行环境不保留文件**（例如每次都是全新容器），凭证会丢，
> 那就每次都要重新问用户。**这不算错误**——如实说明即可，用户再用同一个接入码兑换。
> 接入码有可用次数上限，所以能存住时不要重复兑换。

> 接入码是发到每个人手里的，**不要互相借用**——它决定了报告归到谁名下。
> 用户手上有多个时，用**他自己**那个。

## 标准流程

### 第 1 步：确定是哪场会

用**你自己的飞书能力**找会议（例如 `lark-cli vc +search`）。
用户没说清就列出候选让他选，**不要自己猜**。

### 第 2 步：取妙记的文字转录稿

用**你自己的飞书能力**导出这场会妙记的**文字转录稿**。

**不要退化成 AI 摘要。** 分析只认成员的原始发言（每行形如「姓名 时间 内容」）。
拿摘要去分析会得出假结论——接口也会拒绝。

### 第 3 步：调分析接口

```bash
curl -s -X POST https://meeting.bamamei.online/api/host/v1/analyze \
  -H 'Content-Type: application/json' \
  -H "Authorization: Bearer $(cat "$HOME/.teaming-mcp/host-token")" \
  --max-time 150 \
  -d '{
    "transcript":"<逐字稿原文>",
    "title":"<会议标题>",
    "feishuMeetingId":"<这场会的 meeting_id 或 minute_token>"
  }'
```

> ★ **`feishuMeetingId` 必须传。** 它是幂等键：
> 同一场会重复分析会命中已有报告（不重复消耗、不重复入库）。
> **不传**的话服务端只能用逐字稿哈希当键，而同一场会每次导出的文本常有细微差异
> （时间戳、识别噪声、格式），哈希就变了——**同一场会被当成两场，重复分析、重复建行**。
> 这个 id 从妙记里取（导出转录稿时通常就能拿到）。

> ⚠️ **`--max-time` 至少 150 秒。** 首次分析通常 60~90 秒。
> **超时不等于失败**——服务端往往已经分析完。**重试是安全的**：
> 同一份逐字稿会命中已有报告（`reused: true`），不会重复消耗。

成功返回：

```json
{ "ok": true, "reused": false,
  "reportUrl": "https://meeting.bamamei.online/report/v2/…",
  "zone": "Apathy", "zoneLabel": "可能是冷漠区或舒适区",
  "meetingType": "技术支持/排障", "durationLabel": "7分钟 43秒", "participantCount": 3 }
```

### 第 4 步：汇报

汇报里**必须包含两样**：

1. **四部分结论**：团队状态定位、互动概览、未完成的对话与非共识、给领导者的建议。
2. **★ `reportUrl` 全文，原样贴出来。** 不要缩略、不要省略、不要只写"完整报告："
   然后留空，也不要指望用户自己去别处找。格式：

   **完整报告（含图表）：** <把 reportUrl 全文粘在这里>

   并在后面补一句「点开就是带四象限图和互动网络图的完整报告」。

**不要把整份报告塞进对话**——给结论 + 链接就够了。

> ⚠️ 这条是硬要求。用户拿不到链接就等于没拿到报告；接口返回里
> `reportUrl` 是最重要的交付物之一，漏贴是缺陷不是风格问题。

### 第 5 步：发卡片（用户说「发我」时）

用**你自己的飞书能力**，把报告作为交互卡片发到**用户自己**的单聊会话。

卡片样式固定，**不要自己设计**：

```
标题栏  蓝色
标题    小组会议动力分析报告 已出炉
正文    **会议名称：**<会议标题>
按钮    点击查看报告  →  reportUrl
```

## 自动分析（定时任务）

在定时任务里选中本技能，按这个节奏执行：

1. 用你自己的飞书能力查最近 N 小时内**你自己的**新妙记；按 token 去重，
   与上次已处理过的比对，**只处理新出现的**。
2. 对每场新的：导出转录稿 → 第 3 步调接口（带 `--max-time 150`）。
3. 汇报结论 + `reportUrl`；用户要卡片就按第 5 步发。
4. **查询为空就如实说明**，不要编造数据。

> 幂等由服务端保证（按逐字稿内容哈希）。重复处理同一场会会命中已有报告，
> **不会重复消耗额度**。

---

## 边界

- **不评价个人。** 报告只讲团队层面的互动结构。
- **不做摘要、不做待办。** 那是宿主自己的会议纪要能力。
- **逐字稿不合格就不出结论。** 宁可不分析，也不编造。
- **与 ABC 无关的会由服务端自动跳过**（返回 `not_abc_related`）。这是设计如此，
  **不要重试**，如实告诉用户「这场会不在分析范围内」即可。
