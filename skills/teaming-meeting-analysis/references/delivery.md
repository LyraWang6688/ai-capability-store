# 交付形态：报告怎么给到用户

报告有**两个载体**，别混：

| 载体 | 内容 | 谁提供 |
|---|---|---|
| **网页报告页** | 四部分完整报告 + 四象限图 + 语义互动网络图 + PDF 导出 | 分析接口返回的 `reportUrl` |
| **飞书交互卡片** | 只有一个入口：标题栏 + 一行会议名称 + 按钮 | 由宿主（你）用自己的飞书能力发 |

**卡片是"入口"，报告是"内容"。** 卡片的按钮点出去就是报告页。

---

## 一、报告页链接

分析接口返回：

```
reportUrl = https://meeting.bamamei.online/report/v2/<reportPublicId>
```

**这是唯一的报告链接来源，不要自己拼。**
同一份逐字稿重复分析会返回**同一个** `reportUrl`（幂等）。

汇报时给结论 + 这个链接。**不要把整份报告塞进对话。**

---

## 二、卡片（用户说「发我」时才发）

用**你自己的飞书能力**发到**用户自己**的单聊会话。

### 样式固定，不要自己设计

```
标题栏    蓝色
标题      小组会议动力分析报告 已出炉
正文      **会议名称：**<会议标题>
按钮      点击查看报告  →  reportUrl
```

对应飞书交互卡片 JSON：

```json
{
  "config": { "wide_screen_mode": true },
  "header": {
    "template": "blue",
    "title": { "tag": "plain_text", "content": "小组会议动力分析报告 已出炉" }
  },
  "elements": [
    { "tag": "markdown", "content": "**会议名称：**<会议标题>" },
    {
      "tag": "action",
      "actions": [{
        "tag": "button",
        "type": "primary",
        "text": { "tag": "plain_text", "content": "点击查看报告" },
        "url": "<reportUrl>"
      }]
    }
  ]
}
```

发送方式：`msg_type=interactive`，`content` 为上面这段 JSON。

### 为什么必须固定

线上团队 bot 发的就是这个样式。**加指标块、分区块、报告正文都会让卡片和它不一致**，
用户会以为是两个产品。要看细节就点按钮。

### 只做 2 个元素

| # | 元素 | 内容 |
|---|---|---|
| 1 | `markdown` | `**会议名称：**<标题>` |
| 2 | `action` | 一个按钮 |

**不要再加任何东西。**

---

## 三、发给谁

**发给当前对话的用户本人**，不是别人。

```
用你自己的飞书能力找到【当前账号自己】的单聊会话，发到那里。
```

⚠️ **不要用 MCP 那套凭证去找会话**（如果当前环境有 MCP 的话）：
MCP 用的是它自己的授权，可能是**另一个飞书账号**，那样会发给别人。

判断方法：你能用**自己的**飞书能力搜到这场会、导出妙记，说明你的身份和当前用户同源，
直接用你自己的能力发就对了。

---

## 四、什么时候发

| 场景 | 发不发 |
|---|---|
| 用户说「把报告发我」「推送到飞书」「发我私信」 | 发 |
| 定时任务自动跑完 | 看任务配置：任务里写了"汇报"就汇报结论 + 链接；写了"发卡片"才发卡片 |
| 用户只是问「这场会怎么样」 | 不发，直接汇报结论 + 链接 |
